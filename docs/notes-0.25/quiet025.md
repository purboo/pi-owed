# QT — quiet default output

Scope: what owed prints by default to the parent and to writers. No gate, ledger entry kind, plan key or JSON output changes; everything removed from the default text stays available with `--full`, in the driver log or in JSON.

## Behavior

- Wakes (QT1): each item under "Needs you" is one plain line: the node, what is needed and the one command that clears it. Every open question of a run is its own line with its question and its own answer command, as the asking notice addresses it. A reported node reads `<node> — review the reported findings → owed decide <node> --text "<decision>"`, followed by the report tail the notice carries (the findings are what the parent acts on). Repository-level notices (trunk red, shared failures, trunk drift, including the older unscoped drift notice) are listed under "Needs you" with their full text, every line kept. The raw driver line stays in the driver log and in `owed why`. Merges collapse into one `Done: <nodes>` line instead of riding along as raw merge lines. Quiet text never drops a need or the content needed to act on it.
- `owed why <node>` (QT2): the default card starts with an outcome line (`<node>: <phase>; <n> outstanding` or `nothing outstanding`; `<node>: merged` for a merged node), then one line per unsatisfied obligation, active block and active condition (driver halt with its needs-the-parent/owner wording, hold, wait, a reported node parked with the writer's report and waiting for the parent's `owed decide`, pending rebase, real merge conflicts, out-of-writes paths), each with its reason and the next command, plus unacknowledged model warnings. Every suggested command is one the CLI accepts: trunk invariants (`owed why trunk`, `owed why inv:<id>`) get `owed attest --trunk` when unmeasured and otherwise the plan-repair command the status and decision views give. It ends with `Details: owed why <node> --full`. Satisfied items, observations, logs and counts, driver runs, history, superseded blocks, rulings text, ΔO⁻, model lines and acknowledged warnings appear only with `--full` (CLI flag, pi tool parameter `full`). The JSON card is unchanged. The cards printed after submit, review, attest, waive and merge refusals are unchanged.
- Repair follow-ups (QT3): the message names only failures recorded since the latest repair follow-up to that writer's run that was not refused (ruling steers, report, rebase and interrupted follow-ups and refused sends do not count; before the first repair every failure is new) (failing measured obligations with their failed test names and notes, and active review blocks with the reviewer's note); obligations that still fail from before are named in one line, and if nothing is new it says so. It ends with the next step and points to `owed why <node> --full` instead of embedding the whole card. Rulings since dispatch still come first. The interrupted-reviewer follow-up points to `owed why <node> --full`, since recorded reviews are no longer in the default card.
- Merge (QT4): a successful merge prints `<node> merged (<commit12>); measured <n>, waived <n>, debt <n>` (measured = satisfied check, red, strength, writes and invariant obligations; debt = deferred obligations, still listed on the next line for a single merge), then the lease and unguarded-paths lines. A batch merge prints that line for every merged member (with its own merge commit), then any members not batched and `Batch of <n>: <nodes>`. The ledger entry lines and the full trunk hash are no longer printed. Reading the card for this line happens after the merge is committed and is best-effort: if it fails the line is shortened to `<node> merged (<commit12>)`, and the merge still reports success.
- Answered but still asking (QT5): when a question already has an owed answer recorded at least 10 minutes earlier (plan `drive.answer_grace_s`, now 600 seconds by default) and the subagent host still lists it as open, the wake and its Needs-you line read `<node>: answered at #<seq> (HH:MM), still asking after <m>m: retry with owed answer <node> --rid <rid> --qid <qid> --rev <rev> -- <text>` (the existing exact answer retry), not a new open question. While a driver runs, `owed status` lists the same line under Needs you; it disappears once the run resumes or the slot closes. The driver keeps the observation in a private runtime cache next to its other runtime files; it is not a ledger entry.

## Changed existing tests

- Wake text (QT1): `drive-bg`, `drive-live`, `halt-quiet`, `resume` and `notices` wake assertions now expect the plain Needs-you lines and `Done: <nodes>` instead of raw driver halt, question, launch-rejected and merge lines. The NY4/QN3 notice test now expects the plain owner line with its waive command (the abandon alternative remains in the driver log and in `owed why`) and the new answered-but-asking wording. `quiet` (#1378) expects the plain question line for a plan node named `trunk`.
- `owed why` default (QT2): tests that check full-card content (ΔO⁻, granted writes, template runs, fail notes and block notes, waived items, model lines, range-diff hint, superseded blocks, quarantine lift, ruled-block history, `Untested changes`) now ask for `--full` (`allowances`, `checktpl`, `compactreply`, `counts-exit`, `driver020`, `flow`, `halt-detail`, `models`, `nits022`, `quarantine`, `review-needs`, `supersede`). `models` MD1 negative checks also use `--full` so they still look at the model line. `tool-worker` compares the why tool text with the new default renderer.
- Repair follow-ups (QT3): `drive` row 11 and `review-needs` D18b.2 expect the failure line `- check:unit: …` instead of the embedded card's block line; `repair-epoch` K5 no longer requires an `owed attest` hint in the repair (owed reruns the checks itself), and still requires every attest hint present to carry the driver-skip note; `drive` row 13 expects the interrupted-reviewer message to point to `owed why a --full`.
- Batch merge (QT4): `mtrain` expects one merged line per member and `Batch of 3: a, b, c` instead of the entry lines and `Trunk advanced to …`.
- `review-needs` additionally checks that the default `why` card keeps the needs-parent mark on the blocked review.
- Answer grace (QT5): `notices` QN1 timing moves from the 900-second default to the 600-second default and its retry text to the new wording.

## Decisions / deviations

- QT1: repository-level notices (scope repo, and unscoped legacy drift) are Needs-you items with their full text rather than one plain line, because they carry several nodes and alternatives that one plain line would drop (ruling QT-R1).
- QT1: a reported notice keeps its report tail under the plain line (ruling QT-R1).
- QT1: a single question keeps its designed `owed decide <node> --text "<text>"` command; several questions keep `owed answer … --rid … --qid …`.
- QT2: unacknowledged model warnings stay in the default card (they are alerts, not history); empty merge-conflict lists are omitted.
- QT4: batch merges print the same merged line per member (ruling QT-R1); the line's extra read is best-effort.
- QT5: the 10-minute threshold is the default of the existing `drive.answer_grace_s` (previously 900 seconds), so a plan can still choose another value.
