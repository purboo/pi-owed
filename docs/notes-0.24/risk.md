# Diff-derived review requirements

`risk` is an optional top-level, ordered list of `{paths, review: {count, min_rank}}`. Paths use the writes grammar: literal prefixes, `*`, `?`, and whole-segment `**`. Each changed path of the candidate's slot-base diff uses the first matching rule, otherwise the node's review. The required count and rank are their independent maxima. Classes may lower or raise requirements. An empty diff retains the node's review; it cannot claim membership in a class. Closure-review and existing review blocks remain independent gates.

Adding or changing risk policy in a way that lowers either dimension records `{node: "trunk", what: "risk changed"}`. Only the owner can authorize this, even with a review allowance. Removing a lowering class, raising requirements, and changes to shadowed rules that lower nothing require no downgrade. The comparison respects first-match order, unions, and the writes glob languages. A policy-only change leaves the candidate and all evidence keys intact; current requirements immediately determine which existing reviews suffice.

`closure_neutral` is an optional top-level list of `{path, json_ignore}` with unique exact relative file paths and string dot paths. For a changed closure file on the list, owed parses the base and candidate JSON, removes the named own properties, and requires closure-review only when the remaining parsed JSON differs. Dot segments are literal, including empty segments: `packages..version` addresses the version property in the empty-string package key. There are no wildcards or inherited-property lookups in dot paths. Ignoring one JSON array element does not ignore array length or other elements. Missing files or invalid JSON always require closure-review. A listed file with no ignored paths can still exempt formatting-only JSON changes.

Adding a neutral file or broadening ignored paths records `{node: "trunk", what: "closure_neutral changed"}`, with the same owner-only authority and no allowance coverage. Narrowing/removing ignores is a raise. Updating this policy recomputes open candidate facts through the existing plan carry mechanism; unchanged review/check keys keep their evidence. Check and invariant keys always hash the complete closure file, including ignored JSON properties.

Why, status (including full and JSON), and reviewer packets show the derived count, rank, and contributing class or unmatched path when risk policy is configured. Dispatch packets list the owner's ordered classes. The driver uses the same derived count and rank for reviewer slots, commands, and owner escalation.

Report and report metrics expose `reviews.sameModel`, counting recorded review and closure-review entries whose model matches the writer model for that attempt and review key, ignoring the thinking suffix. Both ok and block entries count, as do multiple obligations recorded by one reviewer. Unknown models are not inferred from driver selections. Report windows filter review entries while still using earlier writer submissions to identify their model. `drive.same_model: accepted` quiets its advisory warning but never removes these counts.

## Compatibility

New optional plan keys: `risk` and `closure_neutral`; new nested fields: `risk[].paths`, `risk[].review.count`, `risk[].review.min_rank`, `closure_neutral[].path`, and `closure_neutral[].json_ignore`. Parsing validates field names, shapes, ranges, writes grammar and exact closure paths. No ledger kind, principal, or optional ledger field is added. New view fields are `reviewRequirement`, `reviewRequirements`, and report/metrics `reviews.sameModel`.

Plans without the new keys retain their candidate facts, review behavior and evidence keys. All executors, drivers and readers must support the keys before enabling them: older readers can ignore unknown plan keys and would derive different requirements. Risk policy itself is never hashed into an evidence key; closure neutrality changes only the closure-review fact and its presence, not the full-file check hashes.

## Existing tests and deviations

`test/parentacts.test.ts` separates the new `reviews` object from its exact legacy-metrics comparison and asserts `{sameModel: 0}` for an unknown-model ledger; all previous field assertions remain unchanged. `test/metrics.test.ts` allows one additional compact-report line for the required same-model count and explicitly asserts that line. The empty-diff fallback, literal empty dot segments, and counting each recorded review obligation are explicit interpretations of the contract. No additional CLI flag is introduced. This node does not implement diff provenance, rebase review carry, shared failures, decision batching, or sweep scheduling.
