Model warning acknowledgements remain informational. Adding or removing `drive.same_model: accepted` preserves the candidate commit and measurement keys; independent review blocks still apply. Pool resolution handles empty, cyclic and nested pools without treating unknown membership as a mismatch. A known member remains a match even when another pool branch cannot be resolved.

Writes grant diagnostics use the optional structured observation field `grant_refused`, rather than interpreting the wording of a failure note. Closure and open-node overlap refusals retain their grant-refused indication when explanatory text changes. An uncovered path alone does not receive that indication. Historical observations without the field continue to replay, without guessing a structured refusal from their text.

Plan set, edit and amend permit an existing invalid legacy writes entry to remain in its original node or allowance position. New invalid entries still refuse, and permission changes retain the existing owner and downgrade checks. Recording a new plan still opts into writes syntax 2, including its wildcard semantics. Runtime copies of a plan retain the writes dialect without adding it to the plan JSON or changing its content hash.

Batch members compare inherited invariant debt with the trunk before the train, rather than an unmeasured intermediate commit. A later single-node merge may use the completed batch's trunk failure to identify existing debt, while measuring its own merge tree independently. New failure names, incomplete failure lists and automatic remeasure conflicts retain their existing refusal rules. Batch observations never carry `remeasure_match` or `auto_remeasure`, and are excluded when a single merge names its first failure in an automatic remeasure diagnostic.

The displayed batch plan excludes nodes waiting for dependencies, nodes marked later, halted or parked nodes and nodes awaiting continuation after a report. A member already being merged in a batch is shown as `merge in batch with <leader>`. Explicit parent/owner batch merges remain available independently of the driver's `drive.merge_batch` setting. Oversized non-final batch ledger lines still trigger completion of the missing members when trunk is at the batch's final commit; a mismatched trunk retains the existing recovery refusal.

The concurrent adopt budget is measured separately for each request, from its pending marker's `since` to process exit. The budget remains 600 ms across lock waits, with an additional scheduling and process-exit allowance in the assertion. Deliberately delaying CLI startup makes the former spawn-to-completion assertion fail, while the request-based assertion passes; both adopters still report a ledger-lock Busy refusal and leave the ledger unchanged.

Existing test expectations changed only where these behaviors require it: the DR3 CLI model-warning test isolates DSA_HOME so host pool configuration cannot affect its unknown-pool expectation; the concurrent adopt budget test measures each request instead of process startup; the legacy brackets/wildcard replay test now accepts a plan recording that retains the original invalid literal, after checking the historical prefix behavior.

Compatibility: `grant_refused` is an optional diagnostic field on existing writes observations. Older readers that reject unknown observation fields must upgrade before reading newly recorded grant refusals. Existing field-free ledgers and plan hashes remain valid. Batch merges and writes syntax 2 retain their existing requirement to upgrade all participating CLI, driver and plugin readers together. The real-ledger replay fixture preserves this repository's original ledger prefix through its first merge, including the original plan blob bytes and hash chain.
