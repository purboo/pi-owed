# 形式化检查

## a3（现行）

a3 的模型、契约和报告都在 `a3/` 下：语义以 `a3/CONTRACT.md`（K1–K14）为准，结果以三份 `a3/REPORT-*.md` 为准。脚本是 `a3/check.sh`，它把每次运行的模块与 cfg 的 sha256 写进日志头。

检查方法：真值性质独立于守卫定义；a22 模式必须违反，a3 必须成立；每条修补单独消融，必须至少翻转一项性质；另设非空见证（预期违反）。脚本化场景只能确认已知漏洞已关上，发现不了未知漏洞，所以 merge 和 auth 另加了"自由交错"模式。

|---|---|---|---|

## 1. PiDag.tla：合入与判定

规则集：`a1`（a1 字面）、`a2`（a2 字面）、`a3`（= ARCHITECTURE a2.1 起的 W 定义）。

环境动作：重派写者（旧写者不死）、任一活写者写好或坏的内容、测试（坏内容可过可不过，相当于 flaky）、评审（准确，可在合入后发生）、父级或 owner 豁免、降级评审义务、追加并修复一条全局不变式、合入。a1 的合入分两步：先求值守卫，再对 trunk 指针做 CAS，律集不在 CAS 中。

| 性质 | 反例 | a1 | a2 | a3 |
|---|---|---|---|---|
| JudgedAdvance：trunk 前进时判定为真 | C8a | ✘ | ✔ | ✔ |
| NegativeWins：有 BLOCK 评审的节点在欠里 | C2 | ✘ | **✘** | ✔ |
| FailIsDebt：有失败观的节点在欠里 | C4 | ✘ | ✔ | ✔ |
| BadVisible：坏内容在回执卡上不会全绿 | C3 | ✘ | ✔ | ✔ |
| OnlyHolderContent：合入内容由当前槽持有者写 | W3 | ✘ | ✔ | ✔ |
| 见证 NoMergeUnderDebt（违反 = 有全局欠时其他节点仍能合入） | C7 | 违反¹ | 违反 | 违反 |
| 见证 NoBadMerged / NothingMerged | 非空 | 违反 | 违反 | 违反 |

规模：2 节点、epoch ≤2、律版本 ≤2，43,132 个状态。a3 另以 3 节点、epoch ≤3、律版本 ≤3 检查了五条安全性质：31,149,916 个状态，深度 28，全部成立。
¹ a1 的守卫要求没有全局欠，但仍能在全局欠下合入，原因同 C8a：守卫先求值，律后变化。

**a2 的反例**：`Downgrade → Write(bad) → Test=pass → Review=BLOCK → Merge`。a2 的 W 第 1 支（豁免）要求"没有同键否定观"，第 2 支（降级）没有这个要求，而"改档等于降级"。修补：豁免和降级统一为"免律"，同一条否定观优先规则同时作用于两者。

## 2. PiDagStrength.tla：证据能否伪造（C1）

隐藏真值：实现 good/bad；测试 strong / strongNew（新模块的强测试）/ weak（能杀掉规定的反事实，但漏掉真实缺陷，即 FAULT-POWER 型）/ vacuous（零用例、`sys.exit(0)`）。写者可以自报任意结果，可以自写测试，也可以自选反事实（例如删掉新模块的 base，任何测试都会死于 ImportError）。准入评审**不**假设准确。

- `a1`：写者自报的回执算数（DESIGN.md:361-364 的自信任），任意反事实上任意非零退出都算强度。
- `a21`：写者的观是言；执行证据要求同键只有 pass；写者自写的测试要先由非写者就该版本立准入律；强度只认律指定的反事实，且失败方式必须是规定的断言失败。

| 性质 | a1 | a21，反事实只能是 base | a21，律可指定 base 或桩候选 |
|---|---|---|---|
| NoVacuousMerged：空测试不能让节点合入 | ✘ | ✔ | ✔ |
| StrongCatches：强测试下坏实现不能合入 | ✘ | ✔ | ✔ |
| 见证 NoWeakEscape：弱测试下坏实现能否合入 | 违反 | 违反 | 违反 |
| 见证 NoWriterTestMerged：写者自写测试能否走通 | 违反 | 违反 | 违反 |
| 见证 NewModuleStuck：新模块的强测试能否合入 | 违反 | **成立（卡死）** | 违反 |

状态数：a21 只用 base 时 4,511；可选桩候选时 9,070（MaxVer=3）。

结论：
- 在给出的环境下，避、格、律指定反事实、规定失败方式这四条足以挡住自报伪造、空测试和自选反事实。
- 弱测试在任何规则下都能逃逸，这就是逃逸类 ①b（证不足）。强度义务只能提高门槛，不能证明测试足够强。
- **新反例（活性）**：如果强度义务的反事实只能是 base，新模块的测试永远给不出"规定的断言失败"，这类叶子会永远留在欠里。修补：律可以指定"桩候选"（目标行为替换为桩）作为反事实。已写入 ARCHITECTURE §3.2。

## 3. PiDagAuth.tla：权

主体为 owner、parent、w1（n1 的写者）、w2（n2 的写者）。律有：授权、撤销（仅 owner；范围为"仅未来"或"追溯"）、豁免、owner 钉住（禁止豁免）。内容可以改版。参照语义 `Reach(t)`：t 时刻在仍存活的授权图上从 owner 可达。

- `lit`：a2.1 的字面读法。授权在作出时检查；撤销的影响范围只覆盖内容和观，不覆盖律；豁免针对义务，不针对内容版本。
- `fix`：权按当前存活的委托链计算；豁免绑定内容版本；追溯撤销会使被切断者签发的豁免失效。

| 性质 | lit | fix |
|---|---|---|
| AuthAtIssue：生效的豁免，签发时作者确有权 | ✘ | ✔ |
| BoundToContent：豁免只覆盖它签发时的内容版本 | ✘ | ✔ |
| RetroHonored：追溯撤销后，被切断者的豁免不再生效 | ✘ | ✔ |
| NoSelfWaive：写者不能豁免自己的节点 | ✔ | ✔ |
| PinWins：owner 钉住后，低权豁免无效 | ✔ | ✔ |
| 见证 NoAgentWaiver：写者能否豁免别人的节点 | 违反 | 违反 |

规模：日志 ≤4 条、每节点 1 次改版，2,780,852 个状态。

lit 的最短反例：
1. **撤销不级联**：`授权 owner→parent，授权 parent→w1，撤销 parent（仅未来），w1 豁免 n2` → 豁免生效。
2. **豁免不绑定内容**：`owner 豁免 n1@v0`，写者改出 v1 → 豁免仍然覆盖 v1。
3. **追溯撤销够不到律**：`授权 owner→parent，parent 豁免 n1，撤销 parent（追溯）` → 豁免仍然生效。

三条修补都已写入 ARCHITECTURE a2.2（Ⅱ 守·权、Ⅱ 守·避、§3.5 撤销）。

见证 `owner→w1 授权，w1 豁免 n2` 说明：避只禁止自己豁免自己，写者之间可以互相放行。这属于策略问题，已列为 §7 待决。

## 没有检查的部分

- 活性的一般形式：每项欠最终都会被兑现者处理；unknown 不活锁（C13）。本次只检查了一个具体的活性反例（新模块卡死）。
- 不增欠的细粒度：全局欠在模型里只是一个布尔值。
- 授权的"缩小"：模型只有一种权利，所以缩小是平凡的。
- 读取集追踪、缓存复用、外部 ref 漂移（C8b）。
- 判断类观察者（评审）的准确性：PiDag.tla 假设评审准确，PiDagStrength.tla 假设准入评审任意。
- fix 规则下的 AuthAtIssue 与参照语义同义，所以这一格只对 lit 有检验意义。
- 结论只在上述有限规模内成立。
