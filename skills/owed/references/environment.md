# Execution environment

Read this topic when the corresponding action or failure is relevant. Return to the [core](../SKILL.md) for the loop and hard rules.

## Quarantine file delivery

Eligible check/invariant runs with active quarantine names receive `OWED_QUARANTINE_FILE`: an absolute private temporary file outside the measured tree, containing sorted exact names, one per line with a final newline. Each execution, including each repeat run, has its own file removed afterward. Own names containing CR/LF remain readable but cannot be delivered; the note says `quarantine file not written: a name contains a line break`. Setup, slot setup, red/mutants, sweep, timeout hooks and jobs without active names have the variable removed, even if inherited or set in `exec.env`.

Scripts may consume it instead of a repository skip list; delivery never changes their exit or excuses anything. Runs without a native protocol say `quarantine file: <n> names (owed excused nothing)`. Natively refused Node/Cargo runs keep `quarantine not applied: <reason>`; Cargo-shaped scripts lacking native syntax keep their Cargo refusal too. An `exec.wrap` container may not see the host path; the wrapper must provide access. A script that skips listed tests cannot report their recovery; only complete native evidence does that. See [evidence](evidence.md) for excusal and recovery scope.

## Wrappers, timeout evidence and caches

Owed measurements automatically take a shared dsa machine lease when available. A leased command receives `OWED_LEASED=1`; wrappers skip nested acquisition for that marker. CLI `--no-lease` or tool `lease:false`, or plan `lease:false`, opts out. Standalone acquisition waits; drivers use no-wait and retry next pass. The marker and lease policy change no evidence key.

Use string `exec.wrap` templates with `{cwd}`, `{timeout}` and required `{cmd}`; substitutions are already POSIX-quoted words, so do not quote them again. Checks/red/mutants/invariants/probes/sweeps/setup/diagnostics are wrapped; Git/worktrees/ledger/lease remain local. Provision remote directories, propagate termination and command exit/output, add no test-protocol output, and return 126/127 if execution never starts; use `red_expect`.

`exec.wrap_grace_s` is a nonnegative integer (default 30): template evidence freezes at timeout, remains timed out during grace, and the local process group is killed by timeout plus grace. Remote cleanup belongs to the wrapper. Templates enter measurement keys verbatim; substitutions/grace do not. Absent templates and legacy argv arrays keep old keys/behavior; upgrade requirements are in [compatibility](compatibility.md).

Command/job runners and destructive/worktree Git operations refuse under the async context's ledger lock, including nested Ledger instances. `advanceTrunk`'s already measured ff-only advance is the single named Git exemption; owed never detaches trunk. Hooks run under that lock and may delay writers; external-process locks cannot be detected by this guard.

On timeout inspect the log's last 256 KiB, `timeout after Ns` and bounded pre-kill process tree (pid/ppid/state/wchan/elapsed/args); the note keeps the last three measurement lines; check/red/invariant timeouts remain error observations, never passing, while strength retains its existing semantics: a timed-out mutant that is not zero-test counts as killed and strength can pass when killed/total meets `min_kill`; macOS ps is best effort, not Linux-tested behavior.

Set check/invariant `on_timeout: "<cmd>"` through the existing plan/edit API for one diagnostic run before kill, limited to 30 seconds in the same tree/env/wrapper; its last 256 KiB is logged but never affects counts, names, signatures, verdict or keys, and hook failure cannot prevent cleanup.

The plan's `exec` block (`env`, `wrap`) applies to every measurement process owed starts. Legacy argv arrays run as `[...wrap, "bash", "-lc", cmd]`; string templates expand their already quoted placeholders through `bash -lc`. Changing environment or wrapper is an owner act (it can weaken every check): the main agent sets it once itself as owner with a plan `note` saying why, and never lets a subagent change it. A wrapper must run the command, pass its output through and exit with its code; when it cannot run the command (transport, mirror or lease failure) it must exit 126 or 127, because any other non-zero code is read as a test failure (a red pass unless `red_expect` is set: use `red_expect` with wrappers). One that runs elsewhere (ssh) must bound the command there itself. A relative `wrap[0]` resolves against the materialized tree: use absolute paths.

Set `exec.parallel: <n>` to measure a merge's (and adopt's, genesis attest's) checks n at once, and `exec.trees: reuse` so measurement trees keep a stable path and build incrementally. Neither is in any key: a parent may change them without owner authority and nothing is re-measured. Do not share an unguarded `CARGO_TARGET_DIR` across reused trees: it can link another checkout's artifacts. Keep a per-tree build dir in the check's `run` (`export CARGO_TARGET_DIR="$OWED_TREE/../target-$(basename "$OWED_TREE")"`; `exec.env` values are not expanded, and a new plan may not set `OWED_TREE`). Low-disk alternative: serialize shared build dirs with `flock` and keep a per-build-dir "last checkout" marker under that lock. When the last builder was another checkout, touch this checkout's tracked files and record this checkout in the marker before building; this covers X@c1 → Y@c2 → X@c1 re-measures that reset alone misses. Leave `exec.touch` unset (default `reset`) so keys stay stable. `exec.touch` (`reset` default, `always`, `never`) refreshes tracked mtimes in reused trees; setting it is an owner act, as it enters the exec key. `owed gc` removes reuse trees the plan no longer needs.
