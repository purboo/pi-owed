# The driver and output

Read this topic when the corresponding action or failure is relevant. Return to the [core](../SKILL.md) for the loop and hard rules.

## Choose an acceptance workflow

Commit small, low-risk fixes off trunk and have the parent record them with one `owed adopt --commit <c> --note "<what changed and why it is acceptable>"` (as delegated owner unless a parent adoption allowance applies). Use owed nodes with independent review and red tests for authentication, concurrency, persistence, deletion/ownership, public contracts and multi-agent waves. Routine evidence and recovery belong to the main agent. Reports to the user name what was delivered and what is genuinely blocked, not routine halts the main agent already resolved.

## Run and recover the loop

`owed drive` (CLI; pi tool `owed_drive` = one pass, `--once`) runs dispatch → writer → submit → attest → reviewers → merge through pi-durable-subagents (≥ 1.0.27) as `parent:drive`. Use `owed start` from a top-level session for the detached loop; run a foreground loop only in a terminal or user service, not in a blocking tool/dsa call. A ruling recorded while a driver writer or reviewer call is running is steered to it (send reason `ruling`); it does not acknowledge anything, so reviewers still pass `ack_rulings`. Answer the node's sole open question with `owed decide <node> --text "<text>"` / `owed_decide`, as parent/owner. For multiple questions or a delivery retry use `owed answer <node> --qid Q --rid R [--rev N] "<text>"` / `owed_answer`; ambiguity refuses. A delivery failure leaves the rule and prints its seq and exact retry command; retry the same rid/qid/rev/text to reuse that revision's rule. The answer is not sent back as a writer ruling to its target rid; reviewer acknowledgment scope is unchanged. The driver never answers a run's question, never waives, never changes the plan, never runs `restart --force`, and never touches a node that needs the owner; it prints those. Attest/merge holds request `hold machine --shared --priority 10 --no-wait`; a confirmed unknown-option refusal falls back once without priority, never rerunning the measured command: a busy machine is retried next pass; an older dsa that rejects `--no-wait` halts the attempt with that error (upgrade dsa). A driver halt (status "Halted (driver)" / Pending owner, `owed why`) clears after a later non-driver, non-executor node action such as submit, review, rebase, abandon or standalone rule/resume. In a decision group only resume clears it, so `--no-resume` preserves it as `held by ruling #N` under In progress, with no halt resume need/wake. `owed resume <node>` releases it; independent obligations, review decisions, questions and debt remain actionable. Fix the cause and use `owed decide <node> --text "<decision>"`; the driver resumes on its next pass (it keeps no verdict in memory). Prefer `owed resume` (pi `owed_resume`) for "measure again / retry / go on": it creates no obligation and restarts the repair budget; `owed resume <node> --after a,b --note "<why>"` waits until all named nodes merge (tool `after` accepts a string or string array); current unmerged dependencies also wait implicitly, with questions still reported. `owed resume <node> --expect report` (tool `expect: "report"`) asks the next writer follow-up for findings and a stop, not a candidate: a successful sealed report without submit wakes the parent with a bounded result tail and parks the node as `reported` until a relevant rule/resume/plan change/abandon. A later submit is handled normally. Park backlog with node `later: true`; remove it to make the node eligible. Idle wakes count ready/open/waiting/reported/later; `drive.idle_rewake_min` defaults to 60 minutes (0 disables reminders). Use `owed decide` when the writer and reviewers must follow and acknowledge a decision. Add `--writer` (pi `owed_decide` parameter `writer: true`) to require action on a named node's open candidate: it is invalidated, the writer gets a ruling follow-up if sealed or a steer if running, and must submit again (the same commit is allowed); reviewers still acknowledge the ruling. `*` stays general guidance and does not invalidate candidates. If a merge already measuring refuses while the node is waiting after `resume --after`, the driver reports `waiting` and records no halt. Halt texts give the call address `to:"<wid>/<key>"` when dsa reported one. A rejected run stays fixed: fix the cause, then `owed abandon <node>`; a rejected send is superseded by a later attempt resume/submit or non-rejected send to the same rid (continue the run, then `owed resume <node>`), and halted nodes still report questions through driver notifies. If `owed drive` refuses because `.git/owed/drive.lock` is held by another host, check that host; only if no driver runs there, remove the lock file by hand (never for a lock of this host: a live driver holds it).

Normally use `owed_start` / `owed start` to preflight and run the DAG. For an already initialized ledger, `owed_drive` with `action: "start"` (CLI `owed drive --detach`) remains the low-level control: it starts the loop driver as a detached background process that survives pi. Standalone CLI start prints the driver's known pi follower or the no-session note only for a running driver; already exited drivers omit the line. Without a pi session, use `owed watch` as a durable command call (see [core](../SKILL.md)). Wait for wakes rather than polling: the session gets one `owed-drive` follow-up message when the driver halts, a node needs the owner, a run asks a question, the driver is stalled, dsa events fail, or the driver exits (merges are listed in the next message); every top-level pi session later opened in the repository follows a running driver and is woken too. Every owed tool call attaches to its target repository, including refusals; session discovery also finds drivers across repositories at most once every ten seconds, using the starting `DSA_SESSION` with `PI_SESSION_ID` as fallback. Session, tool and registry attachment revalidate complete wake lines from at most the last 256 KiB of the current drive log before following from the end; an existing follower preserves deduplication. Sessions inside dsa calls never attach. A decision-held halt no longer wakes the parent; delivery revalidation drops its vanished needs while retaining surviving siblings. Other halts/notifies wake again only when their text changed or the node gained ledger entries not written by the driver; a repeat without new entries rides along with the next message as `(repeat n, no new ledger entries)`. A halt that needs the owner reads `needs the owner (the main agent decides; owed lists the command)` and ends with the commands that resolve it. Other halts read `needs the parent (the main agent acts; owed lists the command)`; manual evidence names the plan's role and offers `or --as owner:pi`. Trunk drift is not a halt: the driver merges nothing and notifies `trunk <name> moved outside owed (…); the main agent resolves it with: owed adopt --note "<why>"` (or, for a rewound trunk, the `git update-ref` that restores it); after the adopt the next pass merges. The main agent makes drift recovery decisions with a reason; CLI defaults to `owner:cli`, tools to `owner:pi`. A ref-restoration hint is only explicit parent/owner recovery after preserving work, never permission to bypass owed. Never poll `action: "status"` (or `owed drive --status`) in a loop; read it only when a message or the user asks. On a wake-up, read `owed_status` / `owed_why <node>`, act on the halt or question as described above (the running driver resumes by itself on its next pass), and do not start a second driver (`owed start` reuses it; low-level drive start refuses while one runs). When the plan will grow (you will add nodes as work proceeds), start it with `stay: true` (`owed drive --detach --stay`): when idle it wakes you once (`idle: …; staying until the ledger changes`) and resumes by itself after your next `owed_plan`, instead of exiting; stop it with `action: "stop"` when the work is done. After `owed_plan`, a line `ready: <ids> (<n>); no driver is running: …` means ready nodes wait and no driver runs: start one if you want them driven. Wakes are held while you are working and delivered when your turn ends, minus what you resolved meanwhile (`(<n> wake(s) resolved before delivery)`). Drift wakes are dropped when trunk equals the ledger commit or the ledger trunk seq advanced; a failed read keeps the wake. `action: "stop"` (`owed drive --stop`) stops it after its current action, `now: true` at once; a stopped or SIGKILLed driver is restarted with `action: "start"`. Prefer starting it from a top-level session (or `systemd-run --user owed drive`): the driver drops `DSA_EXEC`/`DSA_CALL`, but started from inside a dsa call it prints `note: started from inside a dsa call; …` because that call's process containment may still end it with the call.

Answers: an open question uses dsa's current rev; with none open, `--rev N` / tool `rev` (positive integer) retries that prior revision, otherwise the latest rid/qid rule. Re-asks get a new rule/request even for identical text; same-rev different text refuses. Retry hints include `--rev`.

Notices: ledger answers keep queued asking runs quiet; `drive.answer_grace_s` (integer seconds 0..900, default 600) gives one exact retry reminder per rid/qid if still open. Earlier-driver terminal lines ride along while a newer owner runs. Wakes lead with `Needs you`, `Done` and whether the driver continues; reasons/commands appear once without the repeating Details block, with `Next:` last.

Measurements: the driver runs attests and merges in the background while it serves other nodes: at most `drive.measure` at once (plan `drive:` key, default 2) and one merge. A busy attest (machine lease, or another attest of the node running) is retried on a later pass, never a halt. `owed_drive` status and `/owed` list what is in flight (`<node> attest|merge since <time>`). Stop waits for in-flight measurements; `now` aborts them.

Sessions: the driver's runs are listed in the pi session that started it (`DSA_SESSION`, recorded in `drive.lock`, passed as `run --session`); `owed_drive` status and `/owed` say `runs are listed in pi session <id>` or `no pi session: runs show only in pi-durable-subagents status / the CLI`. If another session should see them, stop the driver and start it from that session. An older dsa without `--session` is used without it (one log line, no halt).

`repairing (block #S)` hides Needs you only without an owner-needed condition; guidance precedes any explicitly labelled valid-block override.

Owner approval after dependencies/resume waits is not actionable until they merge; only ⊤ review says an owner decision is needed.

Let merge-ready critical-path nodes preempt only driver-owned trunk attest/unscheduled idle sweeps; scheduled sweeps continue alongside them, but stop before commit on recorded sweep-definition/`every` changes or removal of `every`, without verdict/interruption. Scheduled leases request `--yield`; a yield aborts, records nothing and retries later like busy. Sweep preparation precedes acquisition at the first setup/check command; cleanup ends before release. Status shows merge/measure wait reason and continuous acceptance age.

Ordinary rules/answers immediately notify running roles; audit delivery/failure receipts and exact answer retry command, with no notification retry loop or implicit ack.

Batch `owed resume A,B,C` / `owed_resume {node:["A","B","C"]}` is atomic with shared options; any member refusal records nothing.

## Long commands outside the driver

A long command the parent runs outside owed's driver — a manual attest, merge or full suite — can use a **pi-durable-subagents command call (≥ 1.0.45)** instead of an agent that waits. A command call uses no model, no provider slot and no tokens; it runs asynchronously and wakes the session on exit. Supply the command, target cwd and a bounded timeout, then act on its recorded exit/result. This does not change the driver's own background measurements, machine-lease Busy retries or waits.

Command calls carry subagent environment markers, so owed's parent/owner rails still apply. Executor attest and suites can run there; the current owed CLI refuses a parent/owner merge in such a call, so a manual merge needs an authorized parent execution context outside that marked process. Owner decisions stay with the main agent. Do not remove markers to bypass the rail.

## Quiet needs, evidence and repairs

Ordinary wakes give one `Needs you: <node> — <need> → <command>` line instead of echoing raw driver output. Every open question keeps its text and answer command. Reported nodes keep the findings tail (last 40 lines, at most 4000 characters); repository notices keep their full text and alternatives. Quiet output never drops a need or the content required to act on it. Flaky exec needs name the original failure and attribution pass on the same key, and distinguish the current candidate when its key differs. An older candidate-key flake is held from owner/repair requests until the current candidate has a counted pass; errors keep the hold, current failures take the normal repair route. Same-key/merge-key flakes remain immediate and held blocks still bind acceptance/merge. Combined diagnostics, including wakes, show trunk-red first with parent guidance and the `or owed waive … --accept-risk N` alternative, then shared-check-on-trunk diagnosis, then the full flaky same-key pair, never lost. Shared-check repairs tell the writer to ask the parent instead of changing code outside writes; tracked waivers remain debt, not passes. See [evidence](evidence.md). Merges collapse to `Done: <nodes>`, then driver state, the repository heading and remaining payload. A halt adds `To clear a halt without an obligation: owed decide <node> --text "<decision>" (add --after <node> to wait until that node merges; --no-resume keeps it halted)`; `Next:` stays last. Each question gets its action from its own answer trailer: command-like `answer: owed ...;` inside the question cannot replace it. Unresolved needs-parent reviews give `review asks: <ask>` and one writer-action decision, never the note's introduction.

Default `owed why <node>` shows outcome, outstanding obligations and active blocks/conditions, plus unacknowledged model warnings. It keeps `Ruling to forward:` in full, measurement/merge-wait status and the diff-derived review requirement (context, not a need). The outstanding total counts obligations/active blocks, not merge-wait context or every printed line. Default ΔO⁻ includes only entries after the current dispatch or latest resume; `--full` restores all evidence, older history, superseded entries, ΔO⁻, selected/used models, backlog (`later`) and quarantine lifts. JSON and operation receipt cards remain detailed.

Writer repairs detail only failures since the latest non-refused repair follow-up to that run, with new test/reviewer notes. Ruling steers, report/rebase/interrupted follow-ups and refused sends do not reset the boundary; before the first repair all failures are new. Earlier failures remain named together; an empty delta says so. Rulings come first; the next step is fix, commit, submit, with `owed why <node> --full` for everything else. Owed reruns checks. Restart reconstructs refused sends from retained halt reasons, recent driver reports and durable runner receipts; a refused repair still does not reset the boundary. If all refusal evidence is removed, it cannot be recovered; all failures remain binding.

An answered question still open after `drive.answer_grace_s` (default 600 seconds) reads `<node>: answered at #<seq> (HH:MM), still asking after <m>m: retry with owed answer ... --rid ... --qid ... --rev ... -- <text>`. This is the same QN grace/retry, not a new question. Status gets the line from driver runtime state only while a driver runs; it disappears when the run resumes or slot closes. Absence of a status line without a driver does not prove delivery.

New anonymous merge-check failures show the escaped last non-empty output line (160 characters) in refusals and marked need/notice details; historical unmarked notes retain their rendering. Single and batch CLI merges give `<node> merged (<commit12>); measured <n>, waived <n>, debt <n>` per member; debt counts only this merge's keys. Single merges retain deferred/coverage lines, batches retain dropouts and `Batch of <n>: <nodes>`. The post-commit receipt read is best-effort: if it fails the shortened merged line still means success, not a refusal. No provided current-key count means no debt field.

## Stopped writers

A successful sealed/pruned writer without a current candidate and with outstanding durable wakes gets no submit reminder or stopped/no-submit halt; due repair/ruling/rebase follow-ups still run. The packet gives `pi-durable-subagents run --request owed-<project>-<node>-<attempt>-<name> --wake caller -- <command…>`: start it, then end the turn without submitting. A live driver's status/why show `writer waiting on durable <request>` under In progress with no wait-generated parent wake; seal age uses describe, otherwise first observation per generation, reset on driver restart. Age is display-only; without a driver this is unknown. Non-ok seals retain halt/recovery and name outstanding requests. Otherwise, a successful sealed writer without a candidate gets a submit reminder only when actual HEAD/dirty inspection finds work; clean handed HEAD or unavailable inspection halts. Plan-changed same-commit resubmits keep their route. After a pending-rebase follow-up, handed HEADs are the latest submit (or dispatch base) plus every later rebase's `from`; clean membership halts, otherwise one reminder carries the rebase instruction, then a seal without submit halts. Running writers wait and actual questions keep their answer flow.

Pending-rebase halts send a due named ruling follow-up first. After `owed decide ... --writer` records/resumes and that follow-up is delivered, a later seal without a new submit or outstanding durable wakes halts naming it, with zero extra submit sends, if it is later than both the rebase follow-up and latest resume. This takes precedence over HEAD/dirty inspection, including unsubmitted commits outside the handed set. Ordinary repair/ruling budgets remain binding.

Wakes/default why/status give `writer says: "<final text>"` or `writer gave no final text`, then `owed decide <node> --text "<ruling>" --writer`. The complete reply is flattened: up to 600 Unicode code points in full, otherwise head 200/tail 380 with a late sentence/whitespace/CJK cut for the head; the tail keeps the original ending and adjusts only its start to a nearby whitespace/CJK boundary, with up to three omitted commit/durable IDs each. Escaping and old recorded halts stay unchanged. dsa seal diagnostics add the ended-process total and at most three pid/commands (80 code points each). Full evidence retains the halt cause and failures. Pruned replies require retained runner text. Packets and writer follow-ups instruct questions for decisions outside writes and prohibit known failing submissions; submit reminders say to ask if stopped for a parent decision. No new ledger kind/key or idle-watchdog guarantee is added.

## Models and reviewer runs

The packaged default is `owed-reviewer`, which must record its verdict with `owed review` and may run checks in its own scratch checkout without editing the writer's or main checkout. Set global or node `drive.reviewer.agent` explicitly to keep a custom profile. Use `owed edit --drive --set reviewer.agent=<agent> --note "<why>"` for later launches; recorded launches keep their agent.

After a `review-missing` halt, `owed resume <node>` grants the same sealed run one new verdict follow-up. If it seals without recording again, the driver halts again. Rejected/pruned runs cannot receive follow-ups, so their guidance omits resume. Builtin read-only profile guidance then gives the drive edit to `owed-reviewer` for a new run of a later candidate, followed by owner review and `owed abandon <node>`; editing the agent never replaces the existing run.

Model-warning acknowledgments preserve candidate commits/keys and never clear independent review blocks; unknown pool branches do not invalidate a proved membership match.

Model comparisons ignore `:thinking` and preserve multi-slash ids; selected dsa pool names resolve nested and `{model, afterMs}` members from current `$DSA_HOME/config.json` (default `~/.pi/durable-subagents/config.json`), not a ledger snapshot; any discovered member matches.

Unknown/unreadable/malformed/empty/cyclic/partly unresolved pools cannot prove a mismatch: unmatched used models show `selected <name> (pool membership unknown)`; proved members still match and owed never changes dsa routing.

Use global/node `drive.same_model: accepted` only to acknowledge the advisory same-model warning (other values refuse, absent node key inherits global, no role override needed); compact why hides it, `why --full` restores it, JSON `modelWarnings` keeps `{message, acknowledged:true}` beside strings, and mismatch warnings/gates/evidence remain unchanged.

Models: the plan's `drive:` block picks the writer and reviewer agents (and models) for every node; a node may set its own `drive` (`writer`/`reviewer`, each `{agent?, model?}`). Route routine nodes (docs, mechanical edits, small tests) to cheaper agents or models there and keep the strong ones for contracts, core code and review. A node role that sets `agent` replaces the plan's role (with the node's `model`, or the agent's own default); one that sets only `model` keeps the plan's agent. It is not an obligation: changing it needs no owner, keeps submitted candidates and affects only later launches. `owed why <node> --full` shows `Drive: writer … · reviewer …` for such a node.

## Views, progress and actions

For a morning view, use `owed_brief` (CLI `owed brief [--since seq|ISO]`): outcome and Needs you first, then owner audit acts, merges since `since`, rejected or blocked nodes and how to clear them, work in progress with its age, and totals.

Act replies are brief; use `owed status` for the full list. At five registered, recorded closed attempt worktrees, compact/full status and merge replies show `Housekeeping: <n> finished attempt worktrees; owed gc reclaims them`. This read-only hint is not automatic deletion and omits open/unrecorded/measurement worktrees or failed listings.

Default `owed status` / `owed_status` explains ready dispatch skips using the driver's predicate: writes overlap (with `--allow-overlap`), active-attempt capacity including removed/same-pass slots, or an owner need. Accepted open attempts are `waiting to merge` outside `max`, while all open attempts count toward `2 × max` and reserve writes. With pending merges, status adds `active <a> of max <m>, waiting to merge <p>`; with none it keeps the prior output. Owner-needed ready nodes appear once under Needs you. Current status capacity/ready lines and why use the live recorded `--max` override when available; view callers outside summary/why reads use plan `drive.max`. Defaults omit clean conflict pairs; full/JSON retain them. It shows outcome, parent/owner next actions, progress and current debt; use `owed status --full` / `owed_status {full:true}` for all evidence and historical audit lines (JSON retains existing fields). Status and brief share current merge diagnostics; a defer stays in Debt only while it still applies to the current merge invariant key.

Status/brief keep current-attempt recorded defers visible when rechecking is blocked: `owner defer (not rechecked: trunk moved)` or `(not rechecked: merge conflicts)`; JSON `deferred[].unverified` is `drift` or `conflict`. These are unverified debt, never acceptance evidence.

After an upgrade, the pi restart hint appears once per session per installed version; full status and mismatch refusals retain it.

`status --full` lists `Merge queue` (JSON `mergeQueue`); accepted attempts order by unique unfinished transitive dependent count descending, then continuous `acceptedSince` oldest first and id. `resume --after` waits for dependencies, not a priority override; all gates still apply.

Read ordinary/full status's internal job/local start and `N merges ahead`; JSON `mergeWaiting[id].job` is runtime-only and `.ahead` is recomputed from the current merge queue (accepted predecessors include a running merge, nonqueued nodes omit it); lease waits retain their reason/since and brief keeps its scope.

Read the plan receipt before its board; use `owed_why {full:true}` / `why --full` for quiet weak-confirmation history, and expect each wake reason once.

The full `owed_why {full:true}` / `owed why <node> --full` card lists keys and evidence for each obligation: ✔ measured or reviewed, ⚠ waived, ✘ rejected, ⊥ awaiting observation, ⊤ conflict, ⏸ deferred, ⛔ blocked. E means a pass supported by evidence, W means an owner waiver, and D means remaining debt. Also inspect "Untested changes" and ΔO⁻ (weakened or removed obligations); changes without test coverage must not be described as verified.

The status pending queues are grouped by discharger: parent+writer handle dispatch, submission, and repairs; executor handles attest; reviewer provides independent judgment; owner handles risks and downgrades. Resolve specific obligations from the queues instead of repeatedly trying merge.

Graceful `owed start --restart` and `owed drive --stop` without `--now` signal each driver process (pid + start time) at most once, using `drive.lock.stop-request` under the drive-detach lock. Repeating them waits, never becomes a hard stop. Restart waits for process exit before replacement; a ten-second timeout refuses and says repeating restart is safe. `--now` is still the explicit immediate stop; foreign-host/unverifiable processes refuse.

`owed --version` / `owed version` prints the installed package version without a repository, takes no other arguments/options and does not inspect ledger reader requirements.

## Batches and their recovery

Set `drive.merge_batch: N` (1..8, default 1/off) for driver batches; parent/owner `owed merge A,B,C` explicitly batches regardless of that setting. Members must be accepted with non-overlapping writes, no non-neutral closure changes or remeasure due; conflicts drop out for rebase and individual merge. Read planned batches in full status/JSON `mergeBatch`.

A batch may survive unrelated node-only plan edits during measurement: every intervening plan is canonically compared with non-members removed. Every member field and global policy remains binding; even a transient relevant edit refuses naming the entry/changed part. Facts are recomputed after an unrelated edit; indirect fact changes still refuse. Trunk/slot/candidate CAS and the latest guard remain unchanged.

A failed batch falls back to individual merges; batch votes never block a member, pool with single-merge votes, carry `remeasure_match`/`auto_remeasure`, or consume a member's automatic retry receipt. Each member measures its own tree and gets its own eligible one same-key remeasure. The same failed set remains suppressed on the same trunk while its candidate commits are unchanged. A refused driver batch also isolates its members across trunk changes, new partners and restarts: they merge alone until their candidate commit changes, the node merges or its slot closes. Re-submitting the same commit keeps isolation. Missing/unreadable isolation state means no remembered isolation. Status reads that file and excludes matching candidates from its batch preview. If saving isolation fails, the refusal report adds `(isolation not saved: <error code>)` and the driver keeps isolation in memory.

Batch inherited debt is compared with pre-train trunk for every member; a later single merge can identify old debt from a completed batch's trunk failure while independently measuring its own tree. New failure names, incomplete/truncated lists and automatic retry conflicts still refuse. Replay rejects batch retry metadata, and automatic remeasure hints never select a batch vote as the first single-merge failure.

Planned batches omit dependency/continuation waits, later, halted, trunk-parked and reported nodes; running members say `merge in batch with <leader>`. Batch-tail recovery also handles oversized non-final member lines; a mismatched trunk still refuses with the recovery action.

For an incomplete batch tail, the parent/owner follows owed's full-hash recovery hint to restore trunk ref/history to `batch.final`, first preserving unrelated work. The next owed write completes missing entries; `adopt` cannot repair that tail. Missing history needs explicit recovery. This is a refused-operation recovery, never a normal ref bypass.

## Dispatch races and advisory idle wakes

`owed dispatch` retries CAS refusals with fresh state across plan changes, rechecking membership, hold, readiness, dependencies and ownership overlap each time, at most three total attempts. Non-CAS failures refuse normally. `owed plan`/amend/edit retain the same bound only while plan sha stays unchanged. Dispatch rolls back first; a failed rollback returns immediately. Exhausted driver retries are quiet `retry next pass` reports, never Needs you or halt. Dispatch rollback deletes the new ref with `git update-ref -d refs/heads/<branch> <base>` (atomic compare-and-delete); a moved ref is kept and its CAS failure is reported under the existing `git branch -d` rollback label. Checked-out branches are also kept.

Use `owed idle [--json]` from cron/systemd: exit 0 idle, 3 not idle, 2 usage/missing ledger, 70 internal error. `drive.watch_idle_min` defaults to 15 minutes, 0 disables; it requires open work, no driver/locks/machine holder or matching running/asking labelled call, and old progress. Unknown calls fall back to age/other conditions; failed installed machine inspection stays quiet.

Pi watches used repositories and initialized initial cwd every 120 seconds, wakes only a settled top-level agent, and claims one wake per host/repository/idle period across sessions. New ledger progress permits another wake; rejected delivery releases the claim. Idle is advisory: unlabelled calls and a crash after claiming may hide activity or suppress a wake; it is separate from staying-driver reminders.
