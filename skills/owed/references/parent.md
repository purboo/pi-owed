# Parent and owner acts

Read this topic when the corresponding action or failure is relevant. Return to the [core](../SKILL.md) for the loop and hard rules.

## Delegated owner and candidate pins

**The main agent is the delegated owner.** A human states the task and leaves; no human operates owed. Owner tools (`owed_waive`, `owed_defer`, `owed_adopt`, `owed_approve`, owner `owed_evidence`, `owed_init`, `owed_decoy` commit/reveal, downgrading `owed_plan`) run without a dialog as `owner:pi` and are recorded with channel `delegated`; the brief lists them after outcome and Needs you, so the morning reader audits them. Never ask a human to run an owed command, and never use `--i-am-owner`. Every act that eases acceptance (a plan downgrade: `note`; waive/defer: `reason`; adopt: `note`) must say why — owed refuses it otherwise. Subagents (writers, reviewers, any pi-durable-subagents call) never act as owner or parent: owed refuses those acts in a process with `DSA_CALL`/`DSA_EXEC` (an accident rail, not a security boundary); such a process also cannot record a review or evidence on a node from inside that node's slot worktree (review from the repository root). Never claim `parent:drive` (the driver's identity; refused). When you judge a candidate (review, waive, approve, owner review, evidence), pass the commit you actually read: `candidate` (CLI `--candidate <commit12>`, as every command owed suggests already carries); if the writer submitted again meanwhile, owed refuses with `candidate changed` and records nothing: re-read `owed_why` and judge the new candidate. Only when the environment sets `OWED_CONFIRM=owner` do owner tools ask for confirmation. The pi dialog times out after `OWED_CONFIRM_TIMEOUT` seconds (default 120; 0 disables the limit), recording nothing; continue other work and report a pending decision. CLI owner commands use terminal confirmation under that gate; their default delegated principal is `owner:cli`, while pi tools use `owner:pi`.

## Plans, decisions and allowances

Prefer `owed decide A,B --text "<decision>"` / `owed_decide {nodes:["A","B"], text}` for one ruling, sole-question answers and recovery. Halted/held nodes resume by default; `--no-resume` / `resume:false` preserves the halt as `held by ruling #N` under In progress, without a halt resume need/wake; `owed resume <node>` releases it. Independent obligations, review decisions, questions and debt remain actionable, and vanished queued needs are dropped at delivery revalidation. Add `--writer` for resubmission, `--writes +path` for amend authority, owner `--defer INV` for current merge-key debt, or `--after FIX` / `--remeasure` (both imply resume). All parts validate before one append; delivery follows. Multiple questions on one node need `owed answer --rid R --qid Q`; failed answers use the exact `--rev` retry, not a new decision. Review blocks and ruling acknowledgments still bind.

Keep separate commands when appropriate: `resume` retries without a ruling or requests `--expect report`; `rule` supports global/prospective policy; `answer` selects/retries a question; `amend` still widens writes alone; `edit` changes other plan fields. Decisions cannot combine no-resume with after/expect/remeasure and cannot release a hold with those options.

For a report and pause, use `owed decide <node> --expect report --text "<pause ruling>"` or `owed answer <node> --expect report "<answer>"` (tools `expect: "report"`). Both record the existing report resume for an open writer attempt, like `owed resume --expect report`. A successful report without a new submit wakes once and parks as `reported (resume #n)` until a relevant parent act naming the node. The ruling/answer and resume validate and append together before delivery; a missing open slot or `decide --no-resume --expect report` refuses without recording anything. Answer retries reuse the recorded rule, resume and request id, never adding a report resume to a prior plain answer or reparking after a later parent act. Retrying with `expect: "report"` requires the original recorded report resume.

Fix `bash -n` admission errors in new/changed init/plan/edit/amend commands, including dry runs, setup/slot setup, expanded templates and diagnostics; unchanged legacy commands remain loadable. Static nested Bash scripts are checked without executing expansions; generated/runtime scripts cannot be resolved. Missing Bash warns: install it and record the plan again. Lint is not acceptance evidence.

Amend/decide writes accept bare paths or `+path`; `-path` needs a plan update. A scope is already covered only when equal to or provably contained by an existing write: `src/lib` under `src/*` widens ownership, even though the filename matches. Covered paths report their enclosing entry. All-covered amend changes neither plan nor ledger; all-covered decide records its ruling and requested defer/resume, with no plan entry and `writes unchanged`. For several nodes the remaining additions must be equal after covered scopes are dropped; mismatches name each node's covered/added paths. Real widening retains owner/allowance checks.

An allow rule is not an existing write. Do not amend real additions fully covered by allow.writes: edit task-needed files freely and let owed grant them during measurement.

Treat critical-path write overlap warnings on plan/edit dry-run as guidance to add deps, never acceptance evidence.

Edit brief text with multiline/equals/colon content literally; empty briefs still refuse.

Policy for future work: `owed rule --nodes "*" --prospective "<policy>"` (pi `owed_rule` field `prospective: boolean`) records `prospective: true`, binding only attempts dispatched later; older unsealed writer/reviewer runs get one informational notify without a new ack, while sealed runs receive no such policy on later follow-ups. Removed nodes get no notice; the parent closes their slots. Never combine prospective policy with `--writer`.

An ordinary `*` ruling with only `rulings` debt gets a reviewer re-ack follow-up (or a reviewer launch when none exists), with the candidate and `--ack-rulings <seq>`; block if the writer must change something. Without a review/closure-review obligation, the writer instead gets one ruling follow-up per set and resubmits (the same commit is allowed), advancing `rulings_seen` through those recorded follow-ups only. Report "Status changes" omit nodes merged by the window's end. Owner reviews use `--rank 3`.

Agents must never use `--i-am-owner`. Owner decisions (`owed_waive`, `owed_defer`, `owed_decoy` commit/reveal, `owed_adopt`, `owed_approve`, owner `owed_evidence`, downgrading `owed_plan` with `note`) are the main agent's, delegated and audited; decide them on evidence and write the reason. A subagent never makes them; under `OWED_CONFIRM=owner` without a UI, stop that decision and report it.

The parent may update the plan through a file path with `owed_plan`; only owner may confirm downgrades, except those an `allow:` rule of the current plan covers (the parent records them; they stay in ΔO⁻, labelled `under allowance (plan #S)`). Only the main agent acting as owner may add or widen `allow` rules, and never silently weaken acceptance conditions. owed grants task-needed exact paths covered by current owner `allow.writes` during attest (attempt-scoped, replay-validated; never closure or another open slot); packets show permissions/grants, receipts show `Granted writes` and ΔO⁻ provenance, and uncovered failures suggest an allow rule; a ruling cannot accept them. To widen writes with a decision, prefer `owed decide <node> --writes +path --text "<limit>"` / `owed_decide {nodes:["<node>"], writes:["+path"], text:"<limit>"`: it edits the recorded plan with the same authority as plan/amend, carries an open candidate and records the decision ruling. `owed amend <node> --writes +path --note "<limit>"` / `owed_amend` remains valid for a standalone amendment. Record any pending plan-file edits with `owed_plan` first.

Prefer `owed edit <node> --set path=yaml ... [--unset path ...] [--node-new] [--rule TEXT [--writer]] [--resume [--after a,b] [--expect report]] --note WHY [--dry-run] [--plan FILE]` (pi `owed_edit`). Paths include node `title`, `brief`, `deps`, `writes`, `later`, `review.count`/`review.min_rank`, `drive.*`, `checks.<id>` (whole mapping) and `checks.<id>.<field>`; for invariants use `owed edit --invariant ID --set field=yaml --note WHY`. Use `owed edit --drive --set max=6 --set reviewer.agent=owed-reviewer --note "<why>"` to edit or create the top-level drive mapping; paths are relative to drive and use the plan parser's keys/types. Drive excludes node/nodes/invariant/node-new targets and rule/resume options. Quote YAML assignments in the shell. The edit preserves comments and records plan/carries/rule/resume in one ledger lock, with the same authority and downgrades as `owed plan`; a refusal writes nothing, dry run only previews. Record unrecorded plan-file edits first. `owed amend` still works.

Planning: keep writes strict by default. For integration and packaging nodes, which tend to need entry files, `package.json` or wiring directories, pre-authorize those prefixes at plan time with an `allow` rule, e.g. `allow: [{nodes: ["KB*", "A9-*"], writes: ["app/src/entry/", "package.json"]}]`. Covered task-needed writes are granted by owed without a parent round trip; reviewers block grants outside the node's task. A parent plan update refused only for widened writes ends with `hint: an allow rule {nodes: [...], writes: [...]} in the prior plan would cover this`, ready to paste into the next plan. `owed init` / `owed plan` (and the pi tools, as `warnings`) warn `warning: node <id> has no checks: its acceptance rests on review alone` for each node with no checks and no evidence obligations; nothing is refused or recorded, but give the node a check or evidence when its goal can be measured. A reviewer's ok means the candidate meets the node's goal as its title and brief state it, not only that the writer's report is accurate.

A changed check definition refusal lists the changed fields (`run`, `timeout_s`, `reads`, `tests`, `red_expect`): owed cannot compare commands, so replacing the definition needs owner authority or a matching check allowance. Adding a new check id avoids changing the old definition. Check-less and loop warnings on `owed plan` skip merged nodes; invariant warnings and `owed init` warnings stay unchanged. Cost lint also warns with `warning: ` for reads covering `**`/at least 90% of tracked trunk paths, checks reading base-pinned closure files, and latest trunk passes reaching 80% of an invariant timeout. Use `owed report --cost` to inspect wide/expensive reads; these warnings change no gate.

## Record rebase before the writer applies it

`owed rebase <node>` **without `--apply` already records** the open slot's move from its old base to current trunk and invalidates the candidate; it is not a dry run. The parent/owner or the slot writer may use this manual route. It prints the writer's `git rebase --onto <new> <old>` command, using a computed upstream when HEAD already contains trunk commits. The writer commits work first, runs that exact command in the same slot, resolves only allowed conflicts, and submits again. Blocks still bind the node; setup is not rerun.

Parent/owner `owed rebase <node> --apply` additionally performs the Git rebase and executor submit when the writer is safely idle, HEAD is the current candidate and the worktree is clean. Conflicts/errors roll back before the manual route is recorded; crash leftovers need inspection, never a blind reset. Exact clean rebases may carry independent reviews, never measurements or waivers. The pi rebase tool remains manual.

Submit refuses a commit containing trunk commits after the **recorded slot base**, including a writer's unrecorded trunk merge/rebase. The remedy is a parent `owed rebase <node>` first, then the writer's printed rebase and submit, not another unrecorded Git rebase. When HEAD already contains trunk history, owed advances upstream to avoid replaying other nodes' commits. See SPEC §6.1, §7.25 and §8.

## Finished writer rulings

When `owed rule` sees a node's known writer call neither running nor asking, its receipt names the node/call and says `the ruling was recorded but not sent now; the driver delivers it on its next pass`. A halted node not held by a decision needs `owed resume <node>`; `owed decide <node> --text "<ruling>" --writer` records and resumes in one step. Rule itself never sends a follow-up, and a recorded ruling is not immediate-delivery evidence. The driver sends a due ruling before a pending-rebase stopped-writer halt; a later seal without a new submit or outstanding durable wakes halts naming that ruling follow-up instead of repeating submit reminders. The finished-ruling-follow-up halt also offers `owed decide <node> --expect report --text "<pause ruling>"` to park without that halt. CLI JSON delivery details may include `finished: [{node, writer}]` and full follow-ups; pi tool details retain bounded counts and metadata samples. Read `owed why <node> --full` for the full ruling to forward.

## Initialize and recover genesis

`owed start --plan <file>` preflights Git identity, trunk and plan, initializes a missing ledger as delegated `owner:pi`, records only permitted semantic plan updates, and starts or reuses a detached driver. Omission rereads the latest source; no filename is guessed. An unchanged plan and running driver records nothing. Reusing a driver keeps its original owning pi session; it does not subscribe the caller or transfer ownership. Automatic wakes go only to that owner, including across repositories and on session resume. Explicit CLI `owed watch` observes without taking ownership; missing identity never broadcasts and an absent owner is not taken over automatically. Uncovered downgrades require explicit `owed plan <file> --as owner:pi --note "<why>"`, then start again. Under `OWED_CONFIRM=owner`, fresh start refuses with explicit init guidance without opening a dialog. Warnings share the action line; the tool has three output lines. CLI start adds `followed by pi session <first 8 characters>` or the no-session note directing agents to `owed watch` only for a running driver; already exited drivers omit the line. CLI JSON adds `followedBy: <id> | null`. `max` and `stay` affect only a new driver. `--restart` / tool `restart:true` drains a running driver's action/measurements and waits for process exit before replacing it; a ten-second timeout refuses, says repeating restart is safe, and offers explicit `owed drive --stop --now`. Init/plan recording stays durable if launch fails; do not initialize again. Start's genesis measurements belong to the driver's normal attest/merge lifecycle, not a session-owned background init job.

Initialization is an owner act: call `owed_init` (`plan`) yourself (delegated; a dialog only under `OWED_CONFIRM=owner`; never `--i-am-owner`). After `owed_init` returns, the genesis attest runs in the background; do not poll: `owed_status` shows `Genesis: k/n invariants observed`, and the session gets one `owed-init` message when it ends. `Genesis attest incomplete` means the ledger is initialized: run `owed attest --genesis` (or the next attest/merge measures the missing invariants); never re-run init. Plan edits meanwhile are fine (`owed_plan` warns that genesis is pending).

## Hotfixes and approvals

For a hotfix while the driver runs, keep c off trunk and use `owed adopt --commit <c> --note "<why>"` as delegated owner (or parent under an adopt allowance). Owed waits for the running merge, measures and advances under the merge lock; if c needs rebase, follow the refusal. Already-contained c is `nothing to adopt`. After a crash between ref advance and append, recover with `owed adopt --note "<why>"` without `--commit`.

Use `adopt --wait SECONDS` / tool `wait` for one total acquisition budget (default 60, finite nonnegative fractional seconds allowed) across lease and lock waits, while measurement timeouts stay unchanged. Expiring per-process pending markers make the active driver yield new merges; Busy names activity/local start. Expiry bounds stale foreign markers and PID-reuse limits.

If `owed_status` reports "trunk moved outside owed" (or a merge refuses the trunk CAS naming `owed adopt`), commits were made on trunk outside owed. Do not move refs to work around it. You, the main agent, are the owner: review those commits (`git log`/`git diff` of the range) and, if they belong on trunk, adopt them yourself with `owed_adopt` (`note` saying what they are and why they are acceptable, optional `commit`; delegated, no dialog) or `owed adopt --note TEXT`; list the adoption in your report. If they do not belong, the parent must choose an explicit recovery that preserves unwanted commits before removing their effects; do not treat drift as authority to move refs or discard files. When the plan has an `allow` rule with `adopt` prefixes and every changed path lies under them, the parent may adopt itself: `owed_adopt` with `as: parent:<id>` (no dialog) or `owed adopt --note TEXT --as parent:<id>`. A diverged/rewritten trunk cannot be adopted. Only an explicit parent/owner recovery may restore the ledger trunk using owed's refusal hint, after preserving extra commits on a branch; normal agents never move refs to bypass acceptance. Then redo the work through owed.

Nodes with `approve: owner` (e.g. a publish or push) owe an owner approval: the main agent, as the owner, inspects the candidate and approves it itself with `owed_approve` (or `owed approve <node>`; delegated, no dialog; a UI confirmation only under `OWED_CONFIRM=owner`), giving a `note` and stating the approval and its reason in its report. Subagents never approve, and nobody performs the external effect before the approval is recorded. Nodes with `evidence:` items owe manual evidence: whoever the plan names (`by`: reviewer, parent or owner; never a writer of the node) actually checks it, then records `owed_evidence` (`node`, `id`, `files`, `note`, `as`) or `owed evidence <node> <id> --file <path> --note TEXT --as <role>:<id>`; the files are hashed when recorded. Never record evidence you did not check yourself; it is shown as manual, not as measured. `owed drive` halts for these only when everything else is satisfied. After a merge, record what an external effect produced (version, dist-tag, tarball) as a receipt with the same command (`files` optional, `note` required).

## Closing attempts

If an attempt is a dead end, the parent closes its slot with `owed_abandon` (`node`, optional `reason`); the node can then be dispatched again. To retire a node, remove it from the plan first, then abandon its slot; while deciding, use `owed abandon <node> --hold` (tool `hold: true`), which atomically records abandon plus a `hold` entry and prevents dispatch until `owed resume <node>` releases it without an open slot. The driver quietly closes only its own stale empty slot with no writer launch intent; commits and dirty worktrees are preserved. At five registered, recorded closed attempt worktrees, status/merge show `Housekeeping: <n> finished attempt worktrees; owed gc reclaims them`: a read-only hint, not automatic removal. Periodically run `owed_gc` (first with `dry_run: true`) to remove worktrees and branches of merged or abandoned attempts; it never removes an open slot, a dirty or locked worktree, and it pins submitted commits under `refs/owed/keep/`. Use `owed_verify` to check the ledger hash chain.
