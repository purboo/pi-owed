# owed: No receipt, not done.

**You, the main agent, are the owner (D25).** A human states the task and leaves; no human operates owed. Owner tools (`owed_waive`, `owed_defer`, `owed_adopt`, `owed_approve`, owner `owed_evidence`, `owed_init`, `owed_decoy` commit/reveal, downgrading `owed_plan`) run without a dialog as `owner:pi` and are recorded with channel `delegated`; the brief lists them after outcome and Needs you, so the morning reader audits them. Never ask a human to run an owed command, and never use `--i-am-owner`. Every act that eases acceptance (a plan downgrade: `note`; waive/defer: `reason`; adopt: `note`) must say why — owed refuses it otherwise. Subagents (writers, reviewers, any pi-durable-subagents call) never act as owner or parent: owed refuses those acts in a process with `DSA_CALL`/`DSA_EXEC` (an accident rail, not a security boundary); such a process also cannot record a review or evidence on a node from inside that node's slot worktree (review from the repository root). Never claim `parent:drive` (the driver's identity; refused). When you judge a candidate (review, waive, approve, owner review, evidence), pass the commit you actually read: `candidate` (CLI `--candidate <commit12>`, as every command owed suggests already carries); if the writer submitted again meanwhile, owed refuses with `candidate changed` and records nothing: re-read `owed_why` and judge the new candidate. Only when the environment sets `OWED_CONFIRM=owner` do owner tools ask the human in a dialog (it times out after `OWED_CONFIRM_TIMEOUT` seconds, default 120, recording nothing); then continue other work and report the pending decision.

## When to use owed

Commit small, low-risk fixes directly and have the parent record them with one
`owed adopt --note "<what changed and why it is acceptable>"` (as delegated owner unless
a parent adoption allowance applies). Use owed nodes with independent review and red
tests for authentication, concurrency, persistence, deletion/ownership, public contracts
and multi-agent waves. Routine evidence and recovery belong to the main agent. Reports
to the user name what was delivered and what is genuinely blocked, not routine halts
the main agent already resolved.

Every `owed_*` tool takes an optional `cwd`: the absolute path of a directory inside the target repository (default: the session's working directory). A session started elsewhere passes `cwd` on every call to drive another repository; relative paths such as `owed_plan`'s `plan` and `owed_decoy`'s `file` resolve against it. To submit as the slot writer, pass the slot worktree as `cwd`.

Start with `owed_brief` (CLI `owed brief [--since seq|ISO]`): outcome and Needs you first, then owner audit acts, merges since `since`, rejected or blocked nodes and how to clear them, work in progress with its age, and totals.

Act replies are brief; use `owed status` for the full list.

Default `owed status` / `owed_status` shows outcome, parent/owner next actions, progress and current debt; use `owed status --full` / `owed_status {full:true}` for all evidence and historical audit lines (JSON retains existing fields). Status and brief share current merge diagnostics; a defer stays in Debt only while it still applies to the current merge invariant key.
In 0.16, status/brief keep current-attempt recorded defers visible when rechecking is blocked: `owner defer (not rechecked: trunk moved)` or `(not rechecked: merge conflicts)`; JSON `deferred[].unverified` is `drift` or `conflict`. These are unverified debt, never acceptance evidence.
After an upgrade, the pi restart hint appears once per session per installed version; full status and mismatch refusals retain it.

Merge order (0.16): `status --full` lists `Merge queue` (JSON `mergeQueue`); accepted attempts use derived `acceptedSince` FIFO, with outstanding `resume X --after Y` targets first, then dependent count and id for ties. Use `resume --after` to prioritize an accepted fix without changing the plan; replacement resumes or closed waits remove that priority, and all gates still apply.

For measured workflow outcomes, use `owed report --metrics [--since seq|ISO] [--until seq|ISO] [--json]` (0.15): merged nodes, interruptions/merge, decision vs no-decision halts, merge timing, first-pass acceptance and repairs/merge, computed only from the ledger and plan blobs; since is exclusive, until inclusive.

In 0.17, use `parentActs.perMergedNode` as the gate metric: all non-driver owner/parent acts by class; `grants` counts owed grants, while the old interruptions line is explicitly partial (driver halts + answers).

In 0.16, metrics `--since`/`--until` also accept date-only `YYYY-MM-DD` at UTC midnight.
Metrics halt groups preserve plain-word node ids in prose; they normalize only in node positions (start before `:`, before `/`, after `node ` or `--after `, or the argument of `owed <verb> `).

1. Use `owed_status` (CLI `owed status`) to inspect ready nodes and pending queues. Dependencies must have merge records before dispatch; a verbal claim of completion is not a receipt.
2. Use `owed_dispatch` to dispatch a ready node. Pass its `subagents` object to subagents/dsa: `agent: worker`, `cwd` must be the slot worktree, `isolation: none`, and `task` must contain the complete packet. owed has already created an isolated worktree; do not add another isolation layer.
3. Writers modify only the packet's writes scope, commit their work, and keep the worktree clean. Run `owed submit <node>` or `owed_submit` inside that worktree. A parent submitting on behalf of a writer must explicitly use the slot's `writer:<node>#<attempt>` identity.
   Slot setup (0.16): dispatch runs `slot_setup` (string), else `setup`, in the new worktree with measurement shell/env/wrapper and a 600 s timeout; `slot_setup: false` skips. Success adds a `Setup: ran … (exit 0)` packet line; tracked setup changes refuse with paths and rollback, while new untracked/not-ignored outputs get deduplicated anchored literal common excludes. SS6 verifies they disappear from `git status --porcelain -z --untracked-files=all` (including directory descendants) before reporting `(exit 0; excluded: /a, /b)`, so `git add -A` cannot commit setup artifacts. Tracked `.gitignore` negations (e.g. `!/artifact`) override common excludes: still-visible outputs refuse with one-line escaped names and guidance to ignore setup outputs in the repository or change `slot_setup`. Rollback removes only this dispatch's appended exclude bytes, retains pre-existing rules, removes worktree/branch and records nothing; owed never edits tracked ignore files. Newline/carriage-return output paths refuse with escaped names and rollback. Failure shows exit/timeout and 20 output lines, rolls back and records nothing. `slot_setup` changes no key/candidate; rebase does not rerun it. Owed 0.15 ignores the field and runs no slot setup.
   Large candidates (0.14): review hashing streams the diff with 0.13-compatible UTF-8 semantics; buffered Git output above 256 MiB refuses normally. Optional top-level `limits: {file_mib?, diff_mib?}` sets positive finite MiB limits on the largest changed blob and summed changed blob sizes; submit lists up to five largest files and records nothing on refusal. Limits change no keys; use 0.14+ to enforce them.
Trunk invariants (0.15): `owed attest --trunk` / `owed_attest {trunk: true}` (no node) refreshes current-plan trunk keys and measures changed invariants, abortable and leased; a no-op records nothing. Merge refreshes automatically, retaining trunk observations even on refusal; a quiet driver refreshes too. Named test-only failures already on trunk need no defer, but new names, anonymous failures, timeout/error/count/min_tests failures still refuse. The item stays D with discharger parent and `trunk-red:` detail; `owed status` / `owed why trunk` show when it went red and options (fix node, `known_red` with a fix node, or `owed sweep --commit <trunk>`), and the driver wakes once per invariant/key without halting writers. Before measurement status suggests `owed attest --trunk`; refresh ledgers require 0.15+ (0.14 refuses with `version`).

4. Use `owed_attest` (CLI `owed attest <node>`) for executor measurements. Rerun attribution for original failures first, then process the current candidate. Read logs and rejection reasons; after repairs, commit, submit, and attest (skip this when owed drive is running: the driver attests). Attest exits 75 (`busy`) when that node's attest is already running (the driver's, or another one): its observations will appear in `owed why <node>`; do not retry in a loop. Attests of different nodes run in parallel.
5. Start a fresh, independent reviewer with the current diff, packet, receipt card, and failure evidence. The reviewer must not have been a writer for any attempt of the node. Use `owed_review` with an independent `reviewer:id`, rank, verdict, and note. Closure changes require `closure-review` at rank 2 or higher. Read new rulings and acknowledge their seq with `ack_rulings`. If the brief or plan is ambiguous or contradictory, or the fix needs a product or contract decision, the reviewer blocks with `needs_parent: true` (CLI `--block --needs-parent`) and states the decision needed; it does not push a guess onto the writer. The parent answers with `owed_rule` / `owed rule --nodes <node> "<decision>"` (a `*` ruling does not resolve it); `owed drive` halts on such a block until that ruling exists, then sends the writer a repair that quotes it. After fixing a plan mistake (the brief, writes, a check threshold), or to let a halted writer continue, record a ruling naming the node: it gives the attempt a fresh repair budget and the driver delivers it to the writer (the next repair or follow-up carries it). A driver halt `check <X>: <n> tests ran and passed twice, below min_tests <m>` means the threshold may be the plan's mistake: fix the plan, or rule that the writer adds tests; if the content is acceptable as is, that is the owner's waive, not a ruling.
In 0.17, entirely trunk-red candidates wait without a driver halt; status/brief share one repository notice, trunk movement resumes automatically, and notice deduplication is per driver process (restart may notify once again).
A `trunk-red:` merge refusal (0.14) includes a diagnostic `obs.probe: "trunk"` and both observation seqs: fix trunk (a fixing node or the sweep's bisect/escape proposal), or knowingly `owed waive <node> check:X --accept-risk <merge-tree obs seq>`; the driver parks entirely trunk-red candidates (0.17), never sends this as a writer repair; mixed blocks retain the existing halt behavior. Probes never discharge or block obligations; `status`/`why` recompute classification when trunk moves; an unchanged merge check key can still reuse old-base failure evidence with a new trunk probe. A cleared merge failure can be accepted only when its key still equals the current merge key; the waiver binds only that key, and other cleared/stale risks are refused. `why.mergeChecks` and the status parent queue show refused merge checks separately from candidate acceptance. Use owed 0.14+ for probe ledgers (0.13 refuses the field with code `version`).

Merge refusals (0.16), driver merge-refused halts and `why` blocks name other-tree failures (`known intermittent`, last 5000 entries, newest three seqs) and matching unmerged fix candidates (`owed resume <refused> --after <fix>`; exact names of at least six characters in title/brief/check run/tests). These hints change no gate or ledger field.

6. The parent inspects receipts and actual changes, then uses `owed_merge`. It checks the merge tree, invariants, and trunk CAS; neither review ok nor an accepted candidate replaces the merge guard. After merging, use `owed_report` to report evidence, waivers, and remaining debt.

7. If an attempt is a dead end, the parent closes its slot with `owed_abandon` (`node`, optional `reason`); the node can then be dispatched again. To retire a node, remove it from the plan first, then abandon its slot (allowed since 0.12); while deciding, use `owed abandon <node> --hold` (tool `hold: true`), which atomically records abandon plus a `hold` entry and prevents dispatch until `owed resume <node>` releases it without an open slot. Hold/release entries require 0.14 (0.13 refuses them with code `version`). The driver quietly closes only its own stale empty slot with no writer launch intent; commits and dirty worktrees are preserved. Periodically run `owed_gc` (first with `dry_run: true`) to remove worktrees and branches of merged or abandoned attempts; it never removes an open slot, a dirty or locked worktree, and it pins submitted commits under `refs/owed/keep/`. Use `owed_verify` to check the ledger hash chain.
8. If `owed_status` reports "trunk moved outside owed" (or a merge refuses the trunk CAS naming `owed adopt`), commits were made on trunk directly. Do not move refs to work around it. You, the main agent, are the owner: review those commits (`git log`/`git diff` of the range) and, if they belong on trunk, adopt them yourself with `owed_adopt` (`note` saying what they are and why they are acceptable, optional `commit`; delegated, no dialog) or `owed adopt --note TEXT`; list the adoption in your report. If they do not belong, revert or move them on trunk first. When the plan has an `allow` rule with `adopt` prefixes and every changed path lies under them, the parent may adopt itself: `owed_adopt` with `as: parent:<id>` (no dialog) or `owed adopt --note TEXT --as parent:<id>`. A diverged/rewritten trunk cannot be adopted: restore it (reset the trunk ref to the ledger trunk commit after saving the extra commits on a branch), then redo the work through owed.
8a. Worktree layout (plan `worktrees: {root, branch}`, node `type`): slots may live outside the repository and branches follow a template such as `"{type}/{node}-{attempt}"`. Always use the `worktree` and `branch` that `owed_dispatch` returns (the `owed_dispatch` result details and the CLI `owed dispatch` text carry both, the packet's `Working directory` is the worktree, and `owed status --json` has them under `nodes.<id>.slot`; the status and why texts do not show them); never derive them from `.owed/wt` or `owed/<node>/<attempt>`. Changing `worktrees` or `type` is not a downgrade and affects only later dispatches. If `owed_status` says `Trunk <name> is checked out at <path>; merges fast-forward it there (keep it clean).`, do not write in that worktree; when a merge refuses with `trunk worktree <path> has uncommitted changes`, inspect them: commit them there if they are wanted work, otherwise run `git -C <path> switch --detach` (never discard them), then retry the merge and say what you did in your report.
9. A defect found after a merge is recorded with `owed_escape` (`node`, `merge` = seq of that merge entry, `class`, `note`, optional `evidence`). Decoys belong to the owner: `owed_decoy` with `action: digest` only computes a digest; `commit` and `reveal` are owner acts the main agent makes itself (delegated, no dialog; a UI confirmation only under `OWED_CONFIRM=owner`) — a subagent never does.

10. `owed drive` (CLI; pi tool `owed_drive` = one pass, `--once`) runs dispatch → writer → submit → attest → reviewers → merge through pi-durable-subagents (≥ 1.0.27) as `parent:drive`. Run the long loop in a terminal or a `systemd-run --user` unit, never inside a tool or dsa call. A ruling recorded while a driver writer or reviewer call is running is steered to it (send reason `ruling`); it does not acknowledge anything, so reviewers still pass `ack_rulings`. Answer with `owed answer <node> [--qid Q] [--rid R] [--rev N] "<text>"` (pi `owed_answer {node, text, qid?, rid?, rev?}`), as parent/owner: one answer ruling plus dsa delivery. With one open question selectors may be omitted; ambiguity refuses with the question list. A delivery failure leaves the rule and prints its seq and exact retry command; retry the same rid/qid/rev/text to reuse that revision's rule. The answer is not sent back as a writer ruling to its target rid; reviewer acknowledgment scope is unchanged. The driver never answers a run's question, never waives, never changes the plan, never runs `restart --force`, and never touches a node that needs the owner; it prints those. Attest goes through `hold machine --shared --no-wait`: a busy machine is retried next pass; an older dsa that rejects `--no-wait` halts the attempt with that error (upgrade dsa). A driver halt (status "Halted (driver)" / Pending owner, `owed why`) is cleared by any later action on that node by someone other than `parent:drive` — fix the cause, then e.g. submit, review, rebase, abandon (a new attempt), `owed resume <node> --note "<why>"`, or record a ruling naming the node — and the driver resumes on its next pass (it keeps no verdict in memory). Prefer `owed resume` (pi `owed_resume`) for "measure again / retry / go on": it creates no obligation and restarts the repair budget; `owed resume <node> --after a,b --note "<why>"` waits until all named nodes merge (tool `after` accepts a string or string array); current unmerged dependencies also wait implicitly, with questions still reported. `owed resume <node> --expect report` (tool `expect: "report"`) asks the next writer follow-up for findings and a stop, not a candidate: a successful sealed report without submit wakes the parent with a bounded result tail and parks the node as `reported` until a relevant rule/resume/plan change/abandon. A later submit is handled normally. Park backlog with node `later: true`; remove it to make the node eligible. Idle wakes count ready/open/waiting/reported/later; `drive.idle_rewake_min` defaults to 60 minutes (0 disables reminders). Use a ruling only when the writer and reviewers must follow and acknowledge a decision. Add `--writer` (pi `owed_rule` parameter `writer: true`) to require action on a named node's open candidate: it is invalidated, the writer gets a ruling follow-up if sealed or a steer if running, and must submit again (the same commit is allowed); reviewers still acknowledge the ruling. `*` stays general guidance and does not invalidate candidates. If a merge already measuring refuses while the node is waiting after `resume --after`, the driver reports `waiting` and records no halt. Halt texts give the call address `to:"<wid>/<key>"` when dsa reported one. A rejected run stays fixed: fix the cause, then `owed abandon <node>`; a rejected send is superseded by a later attempt resume/submit or non-rejected send to the same rid (continue the run, then `owed resume <node>`), and halted nodes still report questions through driver notifies (0.16.1). If `owed drive` refuses because `.git/owed/drive.lock` is held by another host, check that host; only if no driver runs there, remove the lock file by hand (never for a lock of this host: a live driver holds it).

    Models: the plan's `drive:` block picks the writer and reviewer agents (and models) for every node; a node may set its own `drive` (`writer`/`reviewer`, each `{agent?, model?}`). Route routine nodes (docs, mechanical edits, small tests) to cheaper agents or models there and keep the strong ones for contracts, core code and review. A node role that sets `agent` replaces the plan's role (with the node's `model`, or the agent's own default); one that sets only `model` keeps the plan's agent. It is not an obligation: changing it needs no owner, keeps submitted candidates and affects only later launches. `owed why <node>` shows `Drive: writer … · reviewer …` for such a node.

11. To run a DAG to completion from pi, call `owed_drive` with `action: "start"` once (CLI `owed drive --detach`): it starts the loop driver as a detached background process (log `.git/owed/drive/log.jsonl`) that survives pi. Then stop working on it and wait to be woken: the session gets one `owed-drive` follow-up message when the driver halts, a node needs the owner, a run asks a question, the driver is stalled, dsa events fail, or the driver exits (merges are listed in the next message); every top-level pi session later opened in the repository follows a running driver and is woken too, while sessions inside a dsa call (subagent writers/reviewers) do not attach by themselves. A halt or notify wakes again only when its text changed or the node gained ledger entries not written by the driver; a repeat without new entries rides along with the next message as `(repeat n, no new ledger entries)`. A halt that needs the owner reads `needs the owner (the main agent decides; owed lists the command)` and ends with the commands that resolve it. Other halts read `needs the parent (the main agent acts; owed lists the command)`; manual evidence names the plan's role and offers `or --as owner:pi`. Trunk drift is not a halt: the driver merges nothing and notifies `trunk <name> moved outside owed (…); the main agent resolves it with: owed adopt --note "<why>"` (or, for a rewound trunk, the `git update-ref` that restores it); after the adopt the next pass merges. A drift halt left by a 0.5.0 driver is cleared with `owed rebase <node>`; you are the owner: run them (CLI owner acts are recorded as `owner:cli`, pi tools as `owner:pi`). Never poll `action: "status"` (or `owed drive --status`) in a loop; read it only when a message or the user asks. On a wake-up, read `owed_status` / `owed_why <node>`, act on the halt or question as in item 10 (the running driver resumes by itself on its next pass), and do not start a second driver (start refuses while one runs). When the plan will grow (you will add nodes as work proceeds), start it with `stay: true` (`owed drive --detach --stay`): when idle it wakes you once (`idle: …; staying until the ledger changes`) and resumes by itself after your next `owed_plan`, instead of exiting; stop it with `action: "stop"` when the work is done. After `owed_plan`, a line `ready: <ids> (<n>); no driver is running: …` means ready nodes wait and no driver runs: start one if you want them driven. Wakes are held while you are working and delivered when your turn ends, minus what you resolved meanwhile (`(<n> wake(s) resolved before delivery)`). Drift wakes are dropped when trunk equals the ledger commit or the ledger trunk seq advanced; a failed read keeps the wake. `action: "stop"` (`owed drive --stop`) stops it after its current action, `now: true` at once; a stopped or SIGKILLed driver is restarted with `action: "start"`. Prefer starting it from a top-level session (or `systemd-run --user owed drive`): the driver drops `DSA_EXEC`/`DSA_CALL`, but started from inside a dsa call it prints `note: started from inside a dsa call; …` because that call's process containment may still end it with the call.

    Answers (0.16): an open question uses dsa's current rev; with none open, `--rev N` / tool `rev` (positive integer) retries that prior revision, otherwise the latest rid/qid rule. Re-asks get a new rule/request even for identical text; same-rev different text refuses. Retry hints include `--rev`. Re-ask rules carry `supersedes` (latest prior answer seq, lower rev); ledgers then require every reader to use 0.16 (0.15 refuses with `version`).

    Notices (0.15): ledger answers keep queued asking runs quiet; `drive.answer_grace_s` (seconds, default 900) gives one exact retry reminder per rid/qid if still open. Earlier-driver terminal lines ride along while a newer owner runs. Wakes lead with `Needs you`, `Done` and whether the driver continues; all original commands and mechanics remain in `Details:`, with `Next:` last.

    Measurements (0.7): the driver runs attests and merges in the background while it serves other nodes: at most `drive.measure` at once (plan `drive:` key, default 2) and one merge. A busy attest (machine lease, or another attest of the node running) is retried on a later pass, never a halt. `owed_drive` status and `/owed` list what is in flight (`<node> attest|merge since <time>`). Stop waits for in-flight measurements; `now` aborts them.

    Sweeps (0.13): optional top-level `sweep: {run, timeout_s, reads?}` runs an advisory suite on detached trunk with `owed sweep [--commit C]` (pi `owed_sweep`), under the shared machine lease. A staying idle driver runs it in the background once per completed trunk sweep; ready driver work preempts it without waiting, and an aborted sweep retries when idle. A confirmed bisect boundary proposes `owed escape` and failing tests to promote, never records an escape or gates a merge; `flaky at head` / `inconsistent (flaky)` names no culprit. Read `Unguarded paths` in merge/driver output and `brief`'s last 10 merges: touched paths no invariant reads cover, report-only, not verified coverage.

    Sessions (pi-durable-subagents ≥ 1.0.31): the driver's runs are listed in the pi session that started it (`DSA_SESSION`, recorded in `drive.lock`, passed as `run --session`); `owed_drive` status and `/owed` say `runs are listed in pi session <id>` or `no pi session: runs show only in pi-durable-subagents status / the CLI`. If another session should see them, stop the driver and start it from that session. An older dsa without `--session` is used without it (one log line, no halt).

12. Nodes with `approve: owner` (e.g. a publish or push) owe an owner approval: the main agent, as the owner, inspects the candidate and approves it itself with `owed_approve` (or `owed approve <node>`; delegated, no dialog; a UI confirmation only under `OWED_CONFIRM=owner`), giving a `note` and stating the approval and its reason in its report. Subagents never approve, and nobody performs the external effect before the approval is recorded. Nodes with `evidence:` items owe manual evidence: whoever the plan names (`by`: reviewer, parent or owner; never a writer of the node) actually checks it, then records `owed_evidence` (`node`, `id`, `files`, `note`, `as`) or `owed evidence <node> <id> --file <path> --note TEXT --as <role>:<id>`; the files are hashed when recorded. Never record evidence you did not check yourself; it is shown as manual, not as measured. `owed drive` halts for these only when everything else is satisfied. After a merge, record what an external effect produced (version, dist-tag, tarball) as a receipt with the same command (`files` optional, `note` required).

The `owed_why` / `owed why <node>` card lists keys and evidence for each obligation: ✔ measured or reviewed, ⚠ waived, ✘ rejected, ⊥ awaiting observation, ⊤ conflict, ⏸ deferred, ⛔ blocked. E means a pass supported by evidence, W means an owner waiver, and D means remaining debt. Also inspect "Untested changes" and ΔO⁻ (weakened or removed obligations); changes without test coverage must not be described as verified.

The status pending queues are grouped by discharger: parent+writer handle dispatch, submission, and repairs; executor handles attest; reviewer provides independent judgment; owner handles risks and downgrades. Resolve specific obligations from the queues instead of repeatedly trying merge.

Policy for future work: `owed rule --nodes "*" --prospective "<policy>"` (pi `owed_rule` field `prospective: boolean`) records `prospective: true`, binding only attempts dispatched later; older unsealed writer/reviewer runs get one informational notify without a new ack, while sealed runs receive no such policy on later follow-ups. Removed nodes get no notice; the parent closes their slots. Do not combine with `--writer`; owed 0.13 and earlier refuse the new rule field with code `version`.

An ordinary `*` ruling with only `rulings` debt gets a reviewer re-ack follow-up (or a reviewer launch when none exists), with the candidate and `--ack-rulings <seq>`; block if the writer must change something. Without a review/closure-review obligation, the writer instead gets one ruling follow-up per set and resubmits (the same commit is allowed), advancing `rulings_seen` through those recorded follow-ups only. Report "Status changes" omit nodes merged by the window's end. Owner reviews use `--rank 3`.

Rules that must not be broken:

- Do not edit closure files to make checks pass; the executor pins the check closure from base. Necessary, genuine closure changes must explicitly receive closure-review acceptance.
- Do not self-review, disguise a writer as an independent reviewer under another name, or fabricate executor evidence.
- Initialization is an owner act: call `owed_init` (`plan`) yourself (delegated; a dialog only under `OWED_CONFIRM=owner`; never `--i-am-owner`). After `owed_init` returns, the genesis attest runs in the background; do not poll: `owed_status` shows `Genesis: k/n invariants observed`, and the session gets one `owed-init` message when it ends. `Genesis attest incomplete` means the ledger is initialized: run `owed attest --genesis` (or the next attest/merge measures the missing invariants); never re-run init. Plan edits meanwhile are fine (`owed_plan` warns that genesis is pending).
- Agents must never use `--i-am-owner`. Owner decisions (`owed_waive`, `owed_defer`, `owed_decoy` commit/reveal, `owed_adopt`, `owed_approve`, owner `owed_evidence`, downgrading `owed_plan` with `note`) are the main agent's, delegated and audited; decide them on evidence and write the reason. A subagent never makes them; under `OWED_CONFIRM=owner` without a UI, stop that decision and report it.
- The parent may update the plan through a file path with `owed_plan`; only owner may confirm downgrades, except those an `allow:` rule of the current plan covers (the parent records them; they stay in ΔO⁻, labelled `under allowance (plan #S)`). Never add or widen `allow` rules yourself (owner only), and never silently weaken acceptance conditions. When `owed why` lists out-of-writes paths, either the writer reverts them or the plan widens writes (a downgrade); a ruling cannot accept them. To widen one node's writes, prefer `owed_amend` (`{node, writes: ["+path", …], note: "<limit>"}`; CLI `owed amend <node> --writes +path --note …`) over editing the plan file: it edits the plan file the ledger last recorded (comments kept), records it with the same authority as `owed_plan`, carries an open candidate, and records a ruling with your limit for the writer and reviewers. Record any pending plan-file edits with `owed_plan` first (amend refuses a file with unrecorded edits).
- Known-red invariants (0.15): `owed edit --invariant ID --set 'known_red=[{test: "exact obs.failed name", fix: repair}]' --as owner:pi --note WHY` records at most 20 unique names as owner-only debt (no `allow` coverage); names change no key. Only failures entirely composed of active listed tests become W/⚠. `status`, `report`, `brief` and JSON `knownRed` list names/fix nodes/plan seq; full status/`lapsedKnownRed` shows removable entries after the fix merges. The fix node cannot merge while its names still fail, even if already trunk-red. Remove repaired entries with `--unset known_red` or a replacement list. Owed 0.14 and older ignore the list and are stricter; upgrade together.
- Atomic plan edits (0.13): prefer `owed edit <node> --set path=yaml ... [--unset path ...] [--node-new] [--rule TEXT [--writer]] [--resume [--after a,b] [--expect report]] --note WHY [--dry-run] [--plan FILE]` (pi `owed_edit`). Paths include node `title`, `brief`, `deps`, `writes`, `later`, `review.count`/`review.min_rank`, `drive.*`, `checks.<id>` (whole mapping) and `checks.<id>.<field>`; for invariants use `owed edit --invariant ID --set field=yaml --note WHY`. Quote YAML assignments in the shell. The edit preserves comments and records plan/carries/rule/resume in one ledger lock, with the same authority and downgrades as `owed plan`; a refusal writes nothing, dry run only previews. Record unrecorded plan-file edits first. `owed amend` still works.
- Planning: keep writes strict by default. For integration and packaging nodes, which tend to need entry files, `package.json` or wiring directories, pre-authorize those prefixes at plan time with an `allow` rule, e.g. `allow: [{nodes: ["KB*", "A9-*"], writes: ["app/src/entry/", "package.json"]}]`. A writer's writes question then costs one parent plan update and no owner step. A parent plan update refused only for widened writes ends with `hint: an allow rule {nodes: [...], writes: [...]} in the prior plan would cover this`, ready to paste into the next plan. `owed init` / `owed plan` (and the pi tools, as `warnings`) warn `warning: node <id> has no checks: its acceptance rests on review alone` for each node with no checks and no evidence obligations; nothing is refused or recorded, but give the node a check or evidence when its goal can be measured. A reviewer's ok means the candidate meets the node's goal as its title and brief state it, not only that the writer's report is accurate.
- The plan's `exec` block (`env`, `wrap`) applies to every check process owed starts (`[...wrap, "bash", "-lc", cmd]`); like `setup`, changing it is an owner act (it can weaken every check): the main agent sets it once itself as owner with a plan `note` saying why, and never lets a subagent change it. A wrapper must run the command, pass its output through and exit with its code; when it cannot run the command (transport, mirror or lease failure) it must exit 126 or 127, because any other non-zero code is read as a test failure (a red pass unless `red_expect` is set: use `red_expect` with wrappers). One that runs elsewhere (ssh) must bound the command there itself. A relative `wrap[0]` resolves against the materialized tree: use absolute paths.
- Check results: one check may chain `cargo test` and `node --test --test-reporter=tap` (the counts sum, format `mixed`). A non-red check that exits non-zero without running a recognizable test (e.g. a wrong cargo package name, exit 101) is `fail` and its note (shown in `owed why` and the repair message) carries the last 5 output lines: fix the command; exit 126/127 with no count is an `error` (the command never ran). Check processes do not inherit `DSA_*` (except `DSA_HOME`), so owed commands inside a check run as a top-level process.
- Negative observations may only be cleared by the rules. Execution failures require attribution on the original key/commit/base: another failure clears the old block; a pass creates a conflict that only an owner waiver accepting the risk of the corresponding seq clears (the main agent decides it, with a reason).
- Slow merges (0.9): set `exec.parallel: <n>` to measure a merge's (and adopt's, genesis attest's) checks n at once, and `exec.trees: reuse` so measurement trees keep a stable path and build incrementally. Neither is in any key: a parent may change them without owner authority and nothing is re-measured. Do not share an unguarded `CARGO_TARGET_DIR` across reused trees: it can link another checkout's artifacts. Keep a per-tree build dir in the check's `run` (`export CARGO_TARGET_DIR="$OWED_TREE/../target-$(basename "$OWED_TREE")"`; `exec.env` values are not expanded, and a new plan may not set `OWED_TREE`). Low-disk alternative (app feedback §38): serialize shared build dirs with `flock` and keep a per-build-dir "last checkout" marker under that lock. When the last builder was another checkout, touch this checkout's tracked files and record this checkout in the marker before building; this covers X@c1 → Y@c2 → X@c1 re-measures that reset alone misses. Leave `exec.touch` unset (default `reset`) so keys stay stable. `exec.touch` (0.11; `reset` default, `always`, `never`) refreshes tracked mtimes in reused trees; setting it is an owner act, as it enters the exec key. `owed gc` removes reuse trees the plan no longer needs.
- Since 0.11 a failure before the command runs (tree preparation, spawn, `setup`) or a disk-full/quota failure with no failing test counted is recorded as `error` with an `environment: ` note: the driver backs off (1, 2, 5, 10, then 30 min) instead of halting, and skips measurements while free disk is below `drive.min_free_mb`; free space rather than waive. When an execution failure was environmental (a missing build artifact, cache or `node_modules` in owed's fresh measurement worktree), fix the check definition instead of waiving: make the check prepare its own artifacts (`setup` or its `run`) in a plan update. That update supersedes the old block (`#<seq> superseded by plan #<p>` in `owed_why`): no rerun and no waiver; the new definition must pass. Since 0.10 a plan change of only a node's `checks`, `writes`, `type` or `drive` (or plan-wide `setup`/`exec`/`closure`) carries the open candidate (`Carried <node>: …`; `owed_why` shows `carried by plan #P from submit #S`): no resubmit, reviews on unchanged keys still count, and only the changed checks are measured again. A `brief`, `deps`, `review` or other spec change still needs the writer to resubmit. Weakening a check is still an owner downgrade. A flaky block of an unchanged definition still needs the owner's waiver, unless the test itself must change: then `owed_rule` with `nodes: [<node>]` saying what the writer must change. The driver sends a ruling to a sealed writer before any halt, including the owner-needed notify (0.8), The block stays flaky after the fix: a plan change of the check's definition supersedes it, or the owner waives it once the fixed candidate passes. Since 0.11 a waiver's `accept_risk` clears the cited blocks whatever their key, merge keys included: a waived merge-result fail no longer counts on its key, so a pass on that key (the attribution rerun) lets `owed merge` proceed.
- `owed dispatch` and `owed plan` retry CAS refusals themselves, at most three attempts in total, only while the ledger plan sha stays unchanged. Each attempt reads fresh state; dispatch rolls back first. A changed plan or failed rollback is returned immediately. Dispatch rollback deletes the new ref with `git update-ref -d refs/heads/<branch> <base>` (atomic compare-and-delete); a moved ref is kept and its CAS failure is reported under the existing `git branch -d` rollback label. Checked-out branches are also kept.
- A changed check definition refusal lists the changed fields (`run`, `timeout_s`, `reads`, `tests`, `red_expect`): owed cannot compare commands, so replacing the definition needs owner authority or a matching check allowance. Adding a new check id avoids changing the old definition. Check-less and loop warnings on `owed plan` skip merged nodes; invariant warnings and `owed init` warnings stay unchanged.
- Repeated checks/invariants (0.13): `repeat: {runs: N, need: K}` (`1 <= K <= N <= 9`, need defaults to N) measures sequentially in one tree, stopping when K passes are reached or unreachable; errors stop as errors. It is part of the key, refused on red/mutants checks, and honored at merge. Per-run `min_tests` applies; do not sum runs to meet it. `noisy (2/3 passed)` describes disagreement, not a separate block. A column-0 `owed-counts {"pass":2,"fail":1,"failed":["latency gate"]}` supplies counts (last valid line wins; indented/comments ignored); only this format's fail > 0 fails even on exit 0. Names from owed/TAP/cargo lead failure notes with a bounded tail, including reused failing observations. Use 0.13 executors and tools for repeat ledgers: 0.12 silently ignores repeat/run metadata.
- `min_tests` counts one TAP, jest/vitest or pytest summary (the last in the log); cargo `test result:` lines add up. Do not loop a TAP command to reach `min_tests` (`owed_plan` warns about such a check); raise the number of tests or lower `min_tests`.
- A judgment block at rank r may only be cleared by an ok from the original reviewer at rank at least r, or another reviewer at a higher rank. Another reviewer at the same rank cannot clear it. Owner waivers must also reference `accept_risk`.
- Do not directly edit the ledger, blobs, or closure to bypass rejection. Defer only permits a specific merge to retain invariant debt; it is not a pass. Invariants cannot be waived.
