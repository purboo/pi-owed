# owed: No receipt, not done.

Owed records acceptance in one Git repository: what was measured, who independently reviewed it, what the owner waived, and what remains debt. The runner does the work; owed guards the merge. A node is done only when owed shows it merged, not when an agent says it finished.

## Tools and loop

The default `core` profile has seven direct tools:
- `owed_status`: outcome, next actions and progress.
- `owed_why`: what a node still owes; `full:true` for evidence.
- `owed_decide`: parent decision, answer and recovery.
- `owed_drive`: one pass, or start/status/stop the background driver.
- `owed_start`: preflight, init/update plan and start/reuse the driver; `restart:true` drains it first.
- `owed_submit`: submit from the writer's committed, clean slot.
- `owed_review`: independent verdict on the candidate actually read; read rulings before `ack_rulings:"latest"`.

Every owed pi tool, including `owed_status`, full views, dry runs and refusals, bounds content to 48 KiB UTF-8 and details JSON to 8 KiB. Details are compact identifiers, counts and metadata samples. Cut text keeps the outcome first and gives an omitted-byte count and a read-only CLI pointer when a valid target is available, such as `owed status --full` or `owed why <node> --full`. Use CLI `--json` for scripts needing everything; CLI output is unchanged. The successful `owed_dispatch` packet, submit line and args come first byte-exact and are exempt; only its trailing status is bounded. Its packet is content-only, not duplicated in details.

Other tools remain registered but deferred: use `tool_search` when they are not declared, or the `owed <command>` CLI (`owed help`). At session start owed activates reachable `tool_search`, as the host's MCP extension does; if discovery cannot work it falls back to direct tools without removing active tools. At session start and every agent start, missing registered direct tools are restored without removing active tools; unsupported host APIs are left alone. Deferred descriptions and tool-name guidance include the CLI alternative. `OWED_TOOLS=all` makes every tool direct and opts out of search activation.

Write the plan, then `owed start --plan <file>` (later `owed start` rereads its recorded source). The driver runs and automatically wakes only the owning pi session with `Needs you:` / `Done:` lines; use explicit CLI `owed watch` to observe without taking ownership. Act with `owed decide <node> --text "<decision and why>"`, `owed answer`, or the command the line gives; the running driver continues. Use `owed why <node>` for outstanding work and `owed why <node> --full` for evidence. Finish only when owed shows the node merged. Use pi-durable-subagents >= 1.2.0 for structured asks; earlier versions retain plain asks, and versions before 1.1.0 keep 0.28 writer-wait and lease behavior.

Use `owed decide <node> --expect report --text "<pause ruling>"` or `owed answer <node> --expect report "<answer>"` (tools `expect: "report"`) to park the open writer attempt like `owed resume --expect report`: report findings, wake once as `reported`, then stay quiet until a relevant parent act naming the node. Decide's `--no-resume --expect report` refuses. Answer retries reuse the recorded report resume; they never add one to an old plain answer or repark after a later parent act.

Read a clipped question whole with `owed question <node> [qid] [--json]` (a read; wakes and `owed why` point to it). Recording pi tools retry once after an optimistic-concurrency refusal and say `retried once after: <first refusal>`; `owed_plan`, `owed_edit` and `owed_amend` end with `recorded plan #<seq> blob <sha> file sha256 <sha>`.

Stage, then accept: anyone, including a writer or fork, may prepare a decision with `owed stage <node> --file BUNDLE.json` (tool `owed_stage`); the parent reviews `owed stages` and applies one with `owed accept S<n> [--amend TEXT]` (tool `owed_accept`), or every open class-B stage with `owed accept --all-b`, or refuses it with `owed reject S<n> --note TEXT`. Accept re-checks the stage and refuses a stale one (`... — fork again`) or one overlapping an older open stage, then records the plan patch, the decision (ruling suffixed ` [stage S<n>]`) and the `accept` entry together, then the marked appends. With plan `drive.delegate` (`on` wake kinds, `max`, `budget`, `a_acts`, `appends`), the session that follows the driver hands a matching wake to one exact fork of itself (dsa >= 1.3.0, `--origin-session`); the fork stages and stops, and one `owed delegate:` message lists `owed accept S<n>` per stage, or returns the original wake when the fork staged nothing. One fork per node: a node whose fork runs or whose fork's stage is open (not accepted, not rejected) is not forked again; its wake comes as a normal turn. A fork may perform only the A acts `a_acts` enables on its own node (`preferred-answer`, `infra-resume`; `owed overturn <seq>` disables a kind); every other parent/owner act stays yours. See [parent](references/parent.md#stages-and-delegate-forks).

The driver retries transient dsa reads (1 s, 3 s, 9 s; timeout 15000 ms or `OWED_DSA_SHORT_MS`) and halts only after 10 minutes of continuous failure; it takes an attest result from the ledger when the measurements are already recorded, and waits instead of halting while a newer writer generation runs (`stale halt: generation <n> is running` marks an older halt).

With an owner pi session and dsa command runs supporting `--session`, driver attests appear in `/subagents` and restart refusals as command calls named `owed attest <node>`. Request ids are deterministic; exits 0/1/4 retain their meaning and 75 means busy. Without the required session/capability, or after an unsupported launch refusal, one driver line explains the legacy hold/direct fallback. Merge measurement stays in-process. See [driver](references/driver.md) for retry and stop behavior.

Main agent = parent and delegated owner: plans, decisions and acceptance; owner tools default to `owner:pi`, no dialog unless `OWED_CONFIRM=owner`.

Automatic attachment requires the current top-level pi session to own the live driver. Startup, tool calls (including status, why and refusals), ticks and settlement do not subscribe an unrelated session; reusing a foreign driver keeps its original owner. Matching owners still discover live drivers across repositories and attach when resuming the same session. Pi tool starts use the validated current context identity; only when context identity is unavailable do they fall back to validated `DSA_SESSION`, then validated `PI_SESSION_ID`. An invalid supplied context identity does not fall back. CLI `DSA_SESSION`-first identity and lock semantics are unchanged. The current lock's session wins; legacy PI-only registration must match the exact live driver's repository, pid, process start and lock time. Missing identity or unknown ownership never broadcasts, and an absent owner is never taken over automatically. Identity changes discard old followers and queued wakes. A foreign replacement is not followed or read; the owned driver's terminal notice is preserved. Busy buffering, delivery revalidation and per-follower deduplication remain. Idle observation belongs to sessions that observed their own live driver (and can continue after exit), or successfully called explicit `owed_init`; startup cwd and ordinary queries do not arm it. Identity changes discard idle observation, and a foreign live driver suppresses its delivery.

CLI `owed start` / `owed drive --detach` adds `followed by pi session <first 8 characters>` or `note: no pi session follows this driver ...` only for a running driver; an already exited driver omits the line. CLI JSON adds `followedBy: <id> | null` (null after exit). For explicit observation without changing ownership, run `owed watch [--after <offset>[:<ino>]] [--timeout s] [--json]` as a durable command call and end the turn. It reads the drive log; writes no ledger entries and takes no driver lock. Revalidation may write the state snapshot cache. It starts at the current log end unless given a cursor. Exit 0 is a wake/driver exit, 5 a timeout; both print `next: owed watch --after <offset>:<ino>`. Reuse that cursor; on timeout it preserves pending merge `Done:` lines for the next watch. A changed inode starts the current log at zero, and bare offsets still work. Exit 3 means no driver and prints no `next:` line. JSON is `{lines, next, exit}`, with a cursor string. Attachment by the owning pi session at startup, tool calls or registry discovery revalidates complete wake lines from at most the last 256 KiB of the current drive log, then follows from the end; an existing follower preserves deduplication. Reusing an old watch cursor can repeat a wake line. Sessions inside dsa calls never attach automatically.

The packaged default reviewer is `owed-reviewer`, which must record its verdict with `owed review`. Explicit global or node `drive.reviewer.agent` keeps a custom reviewer; agent edits affect later launches. After a missing-review halt, resume gives the same sealed run one new verdict follow-up; rejected/pruned runs cannot receive it. Accepted attempts are `waiting to merge` outside `max`; all open attempts still reserve writes and count toward the `2 × max` cap.

Writer: implement only the packet's scope, commit and submit in its slot worktree. Packets list invariants that read the node's writes using slot-base files and literal new write paths, group broad invariants once, and give `owed check try --invariant <id> --green <your commit>`. Commit code, then evidence, then measure, then report: uncommitted edits are never measured. For a decision outside your writes, ask the parent (your run waits): give `decision_needed` (one sentence), numbered `options` (label, scope, cost, risk; one preferred), `facts`, `tried` and `classification_candidates` with evidence and what remains unproven. Use ask fields when available, else text starting `Decision needed:`. Never submit a candidate you believe fails its checks. When a ruling tells you to stop, pause or wait for a parent prerequisite, do not ask to confirm it; state your status and end your turn.
Reviewer: independently inspect the actual candidate and evidence, record a verdict, never edit.

## Plan authoring and decisions

- Checks/invariants may use `run_file: {path, sha256}` instead of `run`/`template`, with optional `args` (at most 64 strings, no NUL). Use a normal repository-relative path whose segments contain only `A-Z a-z 0-9 . _ @ + , = -`, excluding `.`/`..`, and a 64-lowercase-hex SHA-256. Admission verifies uncached bytes from the current worktree or `plan --rev`; every run installs the pin after setup/overlays with mode 0755. Supply a shebang; helpers still follow reads/closure. Pin/args edits use `checks.<id>.run_file.path`, `checks.<id>.run_file.sha256`, `checks.<id>.args` (omit the prefix for invariants).
- Try the disk plan with `owed check try <node> <check> --red <rev> --green <rev> [--plan <file>]` or `owed check try --invariant <id> ...` (`owed_check_try`); at least one revision is required. Fresh exact-commit trees use no closure/test overlay. Even `red: true` uses ordinary verdicts: red expects fail, green pass; error meets neither. Logs remain; without `--record`, no ledger entries are appended. `owed check try --run '<command>' (--green|--red) <rev> [--min-tests N] [--timeout <seconds>]` uses the same disk plan settings; defaults are one required test and 900 seconds, so zero-test/unknown-count successes do not pass by default. Choose exactly one of node/check, invariant or run. Only committed revisions are measured. Add `--record` to save informational receipts per side (including fail/error), with tree and `receipt #<seq>` in output; invariant/ad-hoc receipts need `--record --for <node>` to appear in that node's `owed why`. Node checks associate automatically. Why lists the newest five receipts, or all with `--full`; cite the receipt for a ruling-ordered measurement. Recording requires an initialized ledger; receipts change no gates, keys or votes. Exit 0/1/2/75 means met/unmet/usage/lease busy; `--no-lease` or plan `lease: false` opts out.
- Optional `selftest: [{commit: <40 or 64 hex>, expect: pass|fail}]` (1–8) runs before recording new/changed checks or fixtures. An unmet expectation or error leaves ledger and edited plan file unchanged; success adds a `selftest/v1` note with the plan. Unchanged checks are not rerun; missing fixtures warn `not self-tested`; previews do not execute them. Fixtures affect no keys, candidates or block supersede and prove no acceptance.
- Top-level `env_signatures: {match: [<regex>], unless: [<regex>]}` is a routing hint only: non-empty match, optional unless, non-empty JavaScript regex strings of at most 300 characters, no flags. Suspect ordinary node-check failures retain their verdict; unsatisfied current-key blocks get attribution before repair, then halt if suspect twice. Red/strength executions, repeat, invariants and probes are excluded. Fix the environment, `owed attest <node> --rerun`, then `owed resume <node>`; full remedies are in `owed why <node> --full`. A pass retains the flaky owner need; an effective waiver prevents suspect routing.
- Node `allow_only: [<path-or-glob>]` caps allow-rule grants, including effective old grants, without narrowing own `writes`. Literals are exact paths; directories use `dir/**`; `[]` grants nothing. `owed decide <node> --allow-only p1,p2 --text "<limit>"` (tool `allow_only`) replaces the cap; an empty value sets `[]`. `owed edit` also accepts it. Adding/provably narrowing needs parent authority; widening/removing needs the owner, never an allowance. Cap changes carry candidates and remeasure writes. Mixed changed/unchanged multi-node cap decisions refuse. Upgrade all readers to 0.30 before recording `writes_syntax: 3` caps.
- `owed edit a,b --set review.count=2 --note "<why>"` applies the same sets/unsets to deduplicated targets, validates only the final plan and records one plan, optional all-target rule and requested per-node resumes. Exact existing CLI IDs and `--node-new` targets stay literal even with commas; use `owed_edit {nodes:["a","b"], ...}` or separate edits for collisions. Tool `nodes` excludes `node`/`invariant`; creation permits one distinct node. Pre-write refusals preserve ledger/file; dry-run shows one diff and downgrades.
- `owed edit --drive --set reviewer.agent=owed-reviewer --note "<why>"` edits or creates the top-level drive mapping. Paths are relative (`max`, `repairs`, `merge_batch`, `reviewer.model`); normal plan validation, authority and downgrade rules apply. It excludes node/nodes/invariant/node-new targets and rule/resume options.
- Review `--ack-rulings` accepts `latest`, one number or a comma list (optionally containing `latest`); lists select their maximum and `latest` selects the latest applicable ruling. Tool `ack_rulings` also accepts a nonempty integer array. Read the rulings first; all forms record one numeric watermark, and malformed lists refuse.
- Structured asks show DECISION, numbered options, context and details before each answer command; reply `"option <n>; <limits>"`. Plain asks retain their flow. After `owed answer`/answering `owed decide`, the observed state may be running, queued, still asking, asking again, sealed or unknown. Only the selected question's call address identifies that call; closed-question retries without it report unknown. A failed describe never resends the answer.

See [SPEC](../../docs/SPEC.md) §§3.0a, 3.4.1, 3.6, 3.10 and 12.5.1 for limits and recovery.

## Six hard rules

1. **Done means merged by owed:** a node is complete only when owed shows it merged; a writer's or reviewer's word is not a receipt.
2. **Stay in your role:** writers write and submit in their own worktree; reviewers review and never edit; only the parent/owner records rulings, decisions, waivers, defers, plans and merges.
3. **Never bypass owed:** do not edit `.git/owed`, move the trunk ref, or commit to trunk outside owed (use `owed adopt` for hotfixes).
4. **Never weaken a check to pass:** do not edit, skip or loosen tests, checks or invariants to turn a failure green; changes to existing tests need the contract's or a ruling's authority and are listed in the notes.
5. **Decide inside owed, with a reason:** answer questions with `owed answer` and decisions with `owed decide`/`rule`, each with a note saying why; a decision only in chat does not exist.
6. **Wait for the wake:** the driver wakes you when something needs you; do not poll status in a loop, and never launch a second writer for a slow or quiet one.
