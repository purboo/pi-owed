# pi-dag 架构推演（草案 a1，2026-10-08）

> 目标：用尽量少的公理推出 PRODUCT v0.3 的全部功能，并且不和 J1 的实证冲突。
> 写法：先给出对象和五条公理，再推导各功能，接着用 J1 的事故逐条检验，最后写明公理推不出什么。

## 0. 一个方程

对任一状态 `s` 和日志位置 `t`，把 `s` 的义务集合唯一地划分成三份：

```
O_t(s) = E_t(s) ⊔ W_t(s) ⊔ D_t(s)

  O 义务：这个状态必须满足的检查
  E 兑现：有受信、可证伪证据的义务        → 回执
  W 豁免：有权者明确放过的义务            → 无回执
  D 欠：其余的义务                        → 待办与待决

接受(s, t)  ⇔  D_t(s) = ∅
```

**产品做的事只有一件：把 D 推到空集，并如实显示 W。** 回执卡、待决队列、晨报、合并门禁、裁决失效、逃逸台账，都是这个划分在不同时间、不同读者上的投影。

## 1. 对象

| 对象 | 定义 |
|---|---|
| **内容** | 不可变的字节，以哈希命名。包括：代码树、测试包、检查规格、策略、计划、日志、截图等。 |
| **指针** | 名字 → 内容哈希。是唯一可变的东西，例如 trunk、节点的写者槽、worktree 的持有者、资源租约。 |
| **日志** `L` | 只追加的事实序列，带 seq 和哈希链。 |
| **事实** | 只有四种（见下）。 |

| 事实 | 谁能写 | 作用 |
|---|---|---|
| **律** Law | 有权者（owner、parent、策略授予的角色） | 定义或修改义务和豁免：计划、修订、裁决、策略、waiver |
| **观** Observation | 受信观察者（执行器、评审者、owner） | 产生证据：执行结果、评审结论、人工验收 |
| **移** Move | 任何人发起，按守卫成立 | 指针的 CAS：合入、认领写者、持有 worktree、租用资源 |
| **言** Speech | 任何人 | 没有权威：派活请求、agent 报告、提问、提醒 |

## 2. 五条公理

**A1 同一。** 能被谈论的东西都按内容寻址。可变的只有指针。
> 不存在“分支 X 上的测试通过”，只存在“对内容 h，检查 c 的结果是 r”。

**A2 记忆。** 唯一的真相是只追加的日志。任何视图都是日志前缀的纯函数：`view = f(L[0..t])`。
> 状态不单独存储，只能从日志重算。历史不改写，只追加新事实。

**A3 观察。** 证据只能由观察者写入，而且必须可证伪：只有当同一检查在某个反事实输入上失败过，一次“通过”才算证据。
> 言不是观；不可能失败的检查不含信息。

**A4 兑现。** `接受(s, t) ⇔ D_t(s) = ∅`。其中 `O_t(s)` 由 `L[0..t]` 中已生效的律决定，且律所引用的检查和策略内容必须来自已接受的状态。
> 被检者不能为自己立法；义务一旦成立就持续有效，直到有律撤销它。

**A5 前进。** 指针只能通过带前值的 CAS 移动，并满足该指针的守卫。trunk 的守卫就是 A4。
> 没有长期持有的锁，只有原子的条件写。

## 3. 推导

符号说明：“⇐ A1+A4”表示该功能由这两条公理推出，不需要额外机制。

### 3.1 验收

| 功能 | 推导 |
|---|---|
| 受信 runner，不采信写者自测 | 写者的报告是言（A3），不能进入 E。 |
| 在干净源码快照上验收 | 证据的键是内容（A1）。脏树没有哈希，所以根本无法成为证据的主语。 |
| 允许可信构建缓存 | 缓存条目也按内容寻址（A1），复用它不改变证据的键。 |
| 只用完整 OID，没有短 SHA | 只存在完整的内容哈希（A1）。短 SHA 在类型上就不存在。 |
| red-first | A3 的反事实一条：同一检查在 base（或 null 实现）上必须失败。 |
| 零用例判失败、`sys.exit(0)` 不算通过 | 这类检查在反事实输入上也会通过，即不可能失败，所以不算证据（A3）。 |
| 验收强度（变异、负例） | 把反事实从 1 个扩展到 n 个，强度就是被拒绝的比例。red-first 是 n=1 的特例。 |
| 多种 red 模式 | 只是反事实的不同选法：base、red-origin、继承契约、null 实现、变异。 |
| “只读评审不算实跑” | 观有不同种类：执行、判断。义务会写明它需要哪一种观（A3、A4）。 |
| 测试先行 | 写者自己写的测试是内容，要先作为律被接受（A4：被检者不能为自己立法），之后才能作为检查。“先冻结契约，再实现”由此推出。 |

### 3.2 合并

| 功能 | 推导 |
|---|---|
| 必须在候选上验证 | 候选 `s' = merge(trunk, leaf)` 是新内容，叶子或 trunk 上的证据键不同，不能转移过去（A1、A4）。 |
| 回归选择 | 义务会持续累积：`O(s') ⊇ O(trunk) ∪ O(leaf)`（A4）。只有输入闭包的哈希变了的义务需要重跑，其余证据按键复用（A1）。**回归选择不是启发式，而是缓存失效。** |
| 证据复用 | 当且仅当键相等。“闭包未变”式的复用 = 由律声明更窄的输入闭包函数，仍然是 A1。 |
| 短锁、PRE 被外部改动时拒绝 | 合入就是 CAS(trunk, PRE, s')（A5），前值变了就失败，不需要锁。 |
| 缺评审就不能合入 | 评审是 O 中的一项，只要它还在 D 中，就不满足 A4。 |
| 合并后再评审 | 合入时为评审义务立一条豁免律，它进入 W，显示为“无回执”；之后补的观再把它转为 E。 |
| 策略从可信基线读取 | A4 的第二句。修改策略本身也是一次状态变更，要按旧策略被接受。 |

### 3.3 写者与资源

| 功能 | 推导 |
|---|---|
| 单写者 | 节点的写者槽是一个指针（A5）。dsa 的自动重派、手动 follow-up、父级临时会话，都必须先对它 CAS。 |
| 旧 attempt 迟到的交付 | 来自非持有者的言，记入日志但不生效（A2、A3）。 |
| worktree 归叶子所有、跨轮次保留 | worktree 是指针，持有者是节点；合入后通过 Move 释放（A5）。 |
| 资源租约、回收孤儿资源 | 资源也是指针（A5）。守卫中含持有者存活条件，持有者退休后租约就可以被 CAS 回收。 |
| 资源进入证据键 | 负载会影响结果（J1 中 load≈16 时测试失败），所以环境和资源是检查输入的一部分（A1），否则证据不可复现。 |

### 3.4 计划、裁决与人

| 功能 | 推导 |
|---|---|
| 节点 | **不是原语。** 节点 = 一组义务 + 一个写者槽 + 一个 worktree 指针。聚合节点没有写者槽；外部节点的义务只能由外部观察者兑现。kind 由此推出。 |
| 依赖与 ready | 依赖就是带类型的义务，例如“需要节点 m 的契约证据”或“需要 m 已合入”。节点在自己的依赖义务都已兑现时 ready。 |
| 计划修订 | 计划修订是一条律，内容按哈希寻址，并指向父修订（A1、A2）。生成器的产出作为内容导入。 |
| 风险档、评审档 | 是策略函数：节点 → 义务种类和反事实深度。 |
| 预算（代码行数等） | 只是另一种检查义务。 |
| 裁决 | 修改 O 或修改兑现者的律。supersede 就是后面再立一条律；撤销一个前提错误的裁决，也是追加新律，O 和 D 随之自动重算（A2）。 |
| 裁决失效 | 新的律让 `D_t(trunk)` 增加若干项。这表现为**新债**，不改写历史接受（A2）。派活包里记录 `H(O_t(n))`，所以一个 attempt 是否过期可以直接比较出来。 |
| 待决队列 | **就是 D，按兑现者分组**：等 owner、等父级、等执行器或资源。三列由此推出。 |
| “按推荐”批量答复 | 一条观同时兑现多项义务。 |
| “授权父级决定” | 一条律，把兑现者从 owner 改为 parent。 |
| 人工验收（“可验收 ≠ 已验收”） | 一项兑现者为 owner 的义务。 |
| 回执卡 | 节点的 O 在 E、W、D 三者之间的划分。执行、强度、评审三个维度，就是义务种类的三个分组。 |
| 晨报 | `ΔD`、`ΔW`、`ΔE` 在 `[t0, t1]` 之间的变化，投影给 owner。 |
| 交接 | 位置 `t1` 处的视图，投影给 agent。它带着 t1，所以能判断自己是否过期。 |
| unknown | 就是没有观（A3）。对账 = 按键查日志，没有就重新请求观。**unknown 永远不会被当作拒收。** |

### 3.5 度量

| 功能 | 推导 |
|---|---|
| 逃逸台账 | 后来追加的观否定了一个已接受状态（或其后代）上的某项义务。合入事实记录了当时的 E，所以回链只是一次查询。 |
| 三类逃逸 | 各自对应一条公理的失效：①同一个键重跑得到不同结果，说明 A3 的观察者不可信或检查不确定；②新增的义务失败了，说明 A4 的 O 不充分；③靠 W 才接受的，就是无回执。 |
| 诱饵 | 人为放入已知 `D≠∅` 的状态，检验 A4 的门是否会把它当成 D=∅ 放过。 |
| 每天待决量 | `|D_owner|` 的每日新增项。 |

### 3.6 与 dsa 的接口

| dsa 改动 | 来源 |
|---|---|
| S1 幂等 submit | 请求本身是内容，键 = `H(request)`（A1）。 |
| S2 事件游标 | 日志位置（A2）。 |
| S3 worktree 的 base 与持有者 | base 是内容（A1），持有者是指针（A5）。 |
| S4 资源租约 | 指针（A5）。 |
| S5 无 agent 的执行 | 观察者（A3）。 |

## 4. 实现只需要四个机制

1. **内容仓**：哈希、存储、输入闭包。
2. **日志与归约器**：只追加，带哈希链；视图是纯函数。
3. **观察协议**：受信执行加反事实执行，写入观。
4. **CAS 指针**：trunk、写者槽、worktree、资源。

其余功能都只是事实类型或查询。新增需求时，先问它是不是一种新的律、观或义务，而不是新增一个机制。

## 5. 用 J1 检验（14 条已核实事故）

| 事故 | 结论 | 理由 |
|---|---|---|
| 验收时 README 漂移 | ✔ | A1：证据的主语是快照，不会漂移 |
| 8 位 SHA | ✔ | A1：短哈希在类型上不存在 |
| W3 双写者 | ✔，有条件 | A5：前提是 dsa 的所有启动路径都先 CAS 写者槽 |
| 父级重入锁 | ✔ | A5：只有 CAS，没有跨验收持有的锁 |
| dirty 结果被复用 | ✔ | A1 |
| K4 回归漏选 | ✔ | A4 义务累积 + A1 闭包失效，k4 sweep 已经是一项已存在的义务 |
| PLAN2 集成回归 | ✔ | 同上 |
| FAULT-POWER oracle 过宽 | ✔，有条件 | A3 反事实：要求有反事实集（变异或负例），而且评审义务在合入前必须兑现 |
| BASELINE 身份只信标签 | ✔，有条件 | A3：反事实可以是“篡改标签”，前提是有人把这一项定义出来 |
| K15 新边界未注入 | ✔，有条件 | 需要一条律：“新增持久化边界必须进入注入清单”，并配一项检查 |
| maxBuffer：只测小 fixture | ✘ 推不出 | 没人声明“真实尺寸输入”这项义务（见 §6） |
| 父级误读计划，派错 case | ✘ 推不出 | 律的前提是错的 |
| epoch 裁决 R1 有误 | ✘ 推不出，但收尾干净 | 错误的律经 supersede 后，D 会自动重算 |
| 期限 resume 立即到期 | ✘ 不归 pi-dag | 是 dsa 的生命周期问题 |

合计：7 条直接推出，3 条在补全义务的前提下推出，4 条在边界之外。v3 卖点里“十类挡住八类”的说法不成立；这张表是新的、可以复核的版本。

## 6. 公理推不出的东西

1. **义务是否充分。** 系统只对已声明的义务可靠：**说了的都兑现，没说的都显示为没说。** 反事实只衡量已有检查的强度，不能发现缺失的检查。弥补的办法是一个学习回路：逃逸台账里的第②类逃逸，会变成新的义务，以律的形式加入。
2. **律本身对不对。** 律的前提错误（误读计划、错误裁决）由人负责。系统提供的是：律带着前提，被 supersede 后自动重算。
3. **观察者是否可信。** 信任根由策略指定。在同一 OS 用户下，只能防失误和偷懒。
4. **调度、模型、进程恢复。** 这些归 dsa。
5. **不确定的检查。** 同一个键得到不同结果时，系统会显示为冲突，并归为第①类逃逸的嫌疑；怎么处理由律决定。

## 7. 待审问题

- A3 的“可证伪”在什么情况下成本不可接受？是否允许由律声明“这项义务的反事实集为空”？如果允许，这些义务要计入 W 还是单列？
- 义务“持续有效直到撤销”会不会让 O 无限增长？退役靠律，那么回归成本靠什么控制？
- `O_t(s)` 依赖 t。同一状态在不同时刻可能得出不同的接受结论；合入事实固定的是合入那一刻的 t。这和“历史不改写”一致吗？
- 节点不是原语，那么用户看到的“节点”是否还需要一个稳定 ID？目前的答案是：ID 只是义务组的名字，也就是一个指针。
