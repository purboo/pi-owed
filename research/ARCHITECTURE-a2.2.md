## 0. 一式

```
L ⊢ σ   ⟺   O ⊆ E ∪ W
```

读作：**应则证，不证则免，不免则欠；无欠乃成。**（英文按 O = W ⊔ E ⊔ D 读作 **OWED**）

| 符号 | 含义 | 产品里的样子 |
|---|---|---|
| `L` | 账：只增长的断言序列 | 唯一真相 |
| `σ` | 被判的主语：状态 s、变更 PRE→s、节点 n | 一棵树、一次合入、一个任务 |
| `O` 应 | σ 当前应满足的义务 | 回执卡上的全部行 |
| `E` 证 | 已被有效观察满足的义务 | ✔ 实测 |
| `W` 免 | 未证、但被有权者免除或降级的义务 | ⚠ 无回执 |
| `D = O ∖ (E ∪ W)` 欠 | 其余 | 待办、待决、✘ 拒收 |

`⊢` 相对于账的前缀成立：`L[0..t) ⊢ σ` 一旦成立就永远成立，后来出现的不成立只是**新欠**，不会改写历史。这对应法律上的"法不溯及既往"。

**产品只做一件事：让每个 σ 的欠可见、有主、可清偿，并如实显示免。** 回执卡、待决队列、晨报、合并门禁、裁决失效、逃逸台账，都是这一式在不同主语、时间段和读者上的投影。

## 1. 世界

**物只有两种**
- **内容**：不可变的字节，以完整哈希为名。代码树、测试包、计划、策略、派活包、日志文件都是内容。
- **账 L**：只增长的断言序列。每条断言本身也是内容，用哈希链串起来。

**断言只有两类**

| 类 | 形式 | 主语 | 性质 |
|---|---|---|---|
| **观**（认定事实） | 「观察者 a 在输入 k 上执行或审视 c，得到 r」 | 内容 | 有真假、可被反驳；同键的观单调累积，不需要协调 |
| **律**（作出规定） | 「名字 n 由 v₀ 改为 v₁，前提为 P」 | 名字 | 无所谓真假，只会被取代；必须写明前值，需要单一序列 |

计划、策略、裁决、豁免、授权、trunk、写者槽、worktree、资源租约、节点，**都是名字**。
**言**不是第三类：**没有生效的断言都叫言**，比如 agent 的报告、写者自测、迟到的交付、越权的豁免。言照样入账，可以被引用，但没有效力。

## 2. 三公理

### Ⅰ 史

内容与账之外，别无他物。名字的当前值以及一切视图，都是账前缀和内容仓的纯函数：`view = f(L[0..t), C)`。
外部世界（git ref、进程存活、时钟、dsa 日志、机器负载）只能以**观**的形式入账，主语是它在账中的位置，因此天然不可复用。

### Ⅱ 守

一条断言追加在位置 t。只有在 `L[0..t)` 上同时满足下面三条，它才生效：

- **权**：作者有权作这条断言。
  - 权只能来自此前已生效的律，最终追溯到创世律 `L[0]`。
  - 授权只能沿委托链缩小；撤销授权本身也是律。
  - 权按位置 t 处**仍然存活**的委托链计算：从 `L[0]` 出发、沿未被撤销的授权可达。撤销一个委托者，它下游的全部委托随之失效。
  - 律与律冲突时，权高者优先；同权时，后立者优先。
- **据**：它依据的每个名字，此刻仍是它写明的值。
  - 律至少要写明自己主语的前值。
  - 合入还要写明所依据的律集版本：合入那一刻的义务和策略，就是它写明的那一版。
- **避**：任何人不得做自己案件的法官。
  - 观的作者不能是被观内容的作者。
  - 判 σ 所用的检查和策略，不能出自 σ 本身。
  - 豁免的签发者不能是被豁免内容的作者。豁免和观一样，主语是内容 σ：内容一变，旧豁免就不再覆盖。
  - 这里的"作者"指有裁量权的主体（agent、人）；git merge、runner 这类确定性工具不算作者。

### Ⅲ 判

`L ⊢ σ ⟺ O ⊆ E ∪ W`，其中：

- **O**：主语为 σ 的有效律所规定的义务，每项是「谓词 + 判定规则 + 兑现者」。
  - **只有状态不变式沿 trunk 历史继承**，直到有律令其退役。变更义务（写集、red、对 diff 的评审）和节点义务（预算、人工验收）不继承。
  - 祖先关系按 trunk 律的历史定义，不按 git parent（squash 或 rebase 会切断 git 祖先）。
- **E**：同键的观按格 `⊥ < pass, fail < ⊤` 取并，再按该义务的判定规则汇总为"通过"。
  - 默认规则：至少一次通过，且没有同键失败。
  - 有不确定性的检查，由律写明 n 次中至少通过 k 次。
  - ⊤（结果冲突）不算满足。
- **W**：不在 E 中，被有效的**免律**覆盖，且没有同键否定观（免律明确声明覆盖已知失败的除外）。免律有两种，适用同一条否定观优先：
  1. 豁免：义务保留，单独免除。
  2. 降级：在 σ 的基准时刻之后，律删除或降低了这项义务，且它从未兑现。界面标注为"降级"。

  （a2 原稿只给豁免加了否定观优先，没有给降级加。TLC 找到了反例：先降低评审档，评审 BLOCK 之后照样合入。见 `formal/README.md`。）
- **trunk 只能沿已判的变更前进。** trunk 的律只有在 `L[0..t) ⊢ (PRE→s)` 时才生效。变更 PRE→s 的义务定义为：
  - 该变更自身的义务（来自被合入节点），加上
  - **不增欠**：s 的状态欠必须是 PRE 状态欠的子集，即 `D(s) ⊆ D(PRE)`。

  这样，trunk 可以带着旧欠运行、如实显示，但不能新增欠。互不相关的叶子不会被一笔全局新欠冻结。

**推论 0（a1 的方程）**：`O = E ⊔ W ⊔ D` 是一个划分，优先级为 `E ≻ W ≻ D`。界面再把 D 细分为四种：**⊥ 待观察、✘ 已拒、⊤ 冲突、§ 待立法**。

## 3. 由三公理推出的功能

记号：`据` `权` `避` 指 Ⅱ 的子句，`继承` `格` `W₂` `不增欠` 指 Ⅲ 的子句。

### 3.1 观察与证据

| 功能 | 推导 |
|---|---|
| 受信 runner；写者自测不算数 | 避：写者不能观察自己的内容，所以写者自测只是言。 |
| 在物化快照上验收 | 观的主语是观察者自己算出哈希、并在运行期间保持不变的那份内容（Ⅰ）。脏树不会被拒绝，但它物化出来就是另一份内容。 |
| 完整 OID | 名字只有完整哈希（Ⅰ）。言里出现的短 ID 在入口处解析为完整哈希，解析不了就拒收。 |
| 证据复用 = 回归选择 | 继承 + 格：键相同就复用。**键 = 检查 + 实际读取集（含目录枚举）的内容 + 环境类别。** 读取集由执行器追踪得出，律不能声明更窄的闭包（那等于豁免，走 W）。K4、PLAN2 由此挡住。 |
| 可信缓存 | 缓存条目也是观，受权约束：只有受信者能写。 |
| 不确定的检查、重试 | 格 + 判定规则：重试的结果都并入同一个键；冲突为 ⊤，属于欠。 |
| unknown | 就是 ⊥，属于欠，永远不算拒收。重试次数和"超时算失败"由该检查的律写明，避免活锁。 |
| 资源与负载 | 不进入键，因为负载不是内容。它通过租约（名字）和判定规则处理：重型或性能检查要求独占租约，并按 n 中 k 判定。 |

### 3.2 反事实与验收强度

反事实不再是公理，而是一类义务：**强度义务**。它的谓词由下面四条定义，全部来自 守 与 判：

1. **事先由律指定**：反事实集合连同预期结果标签，一起写在律里。
2. **不由被检者产出**（避）：反事实集合不能由写者选择，所以 red-origin 只作诊断，不当作反事实。
3. **失败方式要符合规定**：必须是"目标用例的断言失败"。ImportError、无关报错、exit 2 都不算。
4. **可复现**：按格汇总，偶然失败一次不算。

| 功能 | 推导 |
|---|---|
| red-first | 反事实集合为 {base}、并且只有一个元素的强度义务。 |
| 新模块 | base 上没有这个模块，测试只能死于 ImportError，永远给不出"规定的断言失败"。此时律指定的反事实是**桩候选**：候选内容中目标行为被替换为桩（返回默认值或抛未实现）。只用 {base} 会让这类叶子永远留在欠里（TLC 反例，见 `formal/README.md`）。 |
| 变异、负例、合成错误输入 | 反事实集合包含多个元素；强度就是被正确拒绝的比例。 |
| 零用例、`sys.exit(0)` | 在 base 上不会出现规定的断言失败，所以强度义务留在欠里。 |
| `none` 模式 | 律不配强度义务，回执卡的"强度"一栏显示为空。降级之后则走 W₂。 |
| 判断类的观（评审、人工验收） | 也有强度义务：观察者近期必须在诱饵上给出过正确的 BLOCK（抽样校准，不要求逐次）。观要写明自己是实跑还是只读，义务的谓词规定需要哪一种。 |
| 测试先行 | 避：检查不能出自 σ 本身。写者自带的测试必须先冻结哈希，再由非写者评审后立律；这次评审本身就是立律，属于便宜通道。 |
| 元检查的自举 | `L[0]` 带上元检查的反事实集合，也就是 M0 诱饵，因此第一个契约节点能够进入 E。 |

### 3.3 合入

| 功能 | 推导 |
|---|---|
| 在候选上验证 | 主语是候选状态 s 和变更 PRE→s，叶子上的证据转移不过来；相同键的证据照常复用。 |
| 无锁合入 | 据：trunk 的律写明 PRE 和律集版本。追加到账上是单一序列的原子步，守卫求值和追加发生在同一步。 |
| 外部有人直接推 trunk | Ⅰ：外部 ref 的值以观入账；和账不一致时记为"漂移"欠，兑现者为 owner。 |
| 缺评审不能合入 | 评审义务在欠里。 |
| 合入后再评审 | 先立一条豁免进入 W；评审 BLOCK 之后，按"否定观优先"它退回欠，在 trunk 上显示为新欠。默认策略不允许父级豁免 R2 及以上节点的评审。 |
| 策略从基线读取 | 避：判 σ 的策略不能出自 σ，所以取自 PRE。修改策略本身也是一次变更，按旧策略来判。 |
| 一笔全局新欠不冻结主干 | 不增欠。 |

### 3.4 写者、worktree 与资源

| 功能 | 推导 |
|---|---|
| 单写者 | 写者槽是名字。dsa 的所有启动路径都要以 据（槽的当前 epoch）作为前提。 |
| 迟到或越权的交付 | 据不符，所以是言。 |
| 非持有者的写入 | 交付内容必须来自持有者 epoch 的 worktree。实现上要求**每个 epoch 一个 worktree**，或者 fencing（依赖 dsa 的 S3）。 |
| 租约 | 名字，带期限和 epoch；可重入的含义是同一持有者可以续租。回收需要先有一条观入账："持有者已退出"或"已到期"。释放之后要回收的外部副作用（挂载、进程），作为租约释放的义务。 |
| 路径所有权、跨 owner 修改 | 路径前缀是名字，由律授权。写集是变更义务："diff 只触及被授权的路径"。 |

### 3.5 计划、裁决与人

| 功能 | 推导 |
|---|---|
| 节点 | 一个名字，指向「义务集 + 写者槽 + worktree」。节点种类由此推出：聚合节点没有写者槽；外部节点的兑现者只能是外部观察者。 |
| 依赖与 ready | 依赖是节点义务，谓词是对账的查询，例如"m 已在 trunk 的历史中"。所有依赖义务都在 E 中，节点即 ready。 |
| 计划修订、裁决、supersede | 带前值的律（据）。冲突按权、再按先后裁定。 |
| 撤销与影响范围 | 撤销律时声明影响范围。由范围内的律派生的内容和观（按派活快照 `H(有效律集)` 识别）退回欠。范围为"追溯"时，被切断者签发的律（豁免、降级）也一并失效；范围为"仅未来"时，它们保留。历史判定不变，现状出现新欠。 |
| 律的前提 | 律写明前提 P，P 是对内容的引用（据）。派活包也是内容，可以挂义务，例如"引用的 case 与已接受规格一致"。父级误读计划这类事故就从这里挡。 |
| 义务不可满足、失败归因 | 写者提交可执行的反例（言），执行器复现后升为观，结论是"该义务集在约束下不可满足"或"检查有误"。这项欠的兑现者随之变为立律者，归入"§ 待立法"。 |
| 预算与止损 | 节点义务，谓词定义在账上（例如累计工时）；超出时兑现者是 owner。 |
| 风险档、评审档、默认授权 | 都写在创世策略里，是"节点 → 义务和兑现者"的函数。改档等于删除或降级义务，走 W₂，在界面上可见。 |
| 待决队列 | 欠按兑现者分组：等 owner、等父级、等执行器或资源、等立法。**兑现者 = 能让这项欠离开 D 的最低权限者。** |
| "按推荐"批量答复 | 一条律选定多项裁决；也可以是一条观兑现多项人工验收义务。两者在类型上不同，但界面上可以合并。 |
| 回执卡 | 一个节点在 E、W、D 之间的划分，按执行、强度、评审三类义务分组显示；D 再细分为 ⊥ ✘ ⊤ §。 |
| 晨报 | 一段时间 [t₀, t₁] 内的 ΔE、ΔW、ΔD，**以及被删除或降级的义务 ΔO⁻**。 |
| 交接 | 位置 t₁ 处的视图，带上 t₁，因此能自行判断是否过期。 |

### 3.6 度量

**定理（逃逸穷尽）。** 设 σ 已被接受但实际有错，则必然存在一个未被满足的真实需求 r，并且恰好落入下面一种情况：

| 类 | 条件 | 产品动作 |
|---|---|---|
| ② 应不足 | O 中没有任何义务蕴含 r | 补律，把新义务加入 O |
| ①a 证不实 | 存在义务 o ∈ E 蕴含 r，但 o 的谓词实际为假，原因是检查不确定或观察者不可信 | 改判定规则，或撤销观察者授权（带影响范围） |
| ①b 键不全 | 存在义务 o ∈ E 蕴含 r，但它的证据是按不完整的键复用来的 | 修正读取集追踪 |
| ③ 免 | 存在义务 o ∈ W 蕴含 r（包括降级） | 复核豁免权限 |

- **逃逸台账**：后来追加的观否定了某个已接受 σ 上的义务。要定位到最早出错的祖先，需要重跑二分，不是一次查询就够。
- **诱饵**：按系统之外的事实已知是错的状态。看它会不会被判为已接受，测量的是上面四类逃逸的发生率。
- **每天待决量**：`|D_owner|` 的每日新增项。

### 3.7 dsa 接口

| 需求 | 来源 |
|---|---|
| S1 幂等提交 | 派活是一条律，主语是名字 `dag:<proj>:<node>:<attempt>`，请求内容先作为内容落盘。幂等键用名字而不是请求哈希：用哈希的话，崩溃重放时字节稍有不同就会重复派活，合法的重派反而会被去重。 |
| S2 事件游标 | Ⅰ：dsa 日志属于外部世界，以观的形式按游标导入。 |
| S3 worktree | 每个 epoch 一个 worktree，base 是内容，持有者是名字。 |
| S4 资源租约 | 名字加期限；"持有者已退出"作为观入账。 |
| S5 无 agent 的执行 | 观察者。 |

## 4. 实现只需要四件东西

1. **内容仓**：哈希、存储，以及执行器的读取集追踪。
2. **账与归约器**：单写者追加、哈希链、权据避检查、视图纯函数。
3. **观察者**：受信执行、反事实执行、判断类观察者的诱饵校准。
4. **外部对账**：git ref、dsa、进程、挂载。都按"先写意图律 → 再做外部动作 → 最后记结果观"的 outbox 方式处理。

新增需求时，先问三个问题：它是一种新的律？一种新的观？还是一种新的义务谓词？三者都不是，才考虑加机制。

**成本**（数字来自 j1-replay）：
- 确定性检查：每个检查版本做一次反事实，结果可缓存，约等于 J1 现状。
- 实现叶的变异由执行器重跑：每版本约 0.2–9 h。
- 回归失效带来的重跑：约 10–19 h，占 J1 墙钟的 6–11%。
- 重型矩阵：只能每版本跑一次，不能每次合入都跑。
- 性能检查和判断类观：只能靠判定规则和抽样诱饵，不能逐次做反事实。

**owner 待决量**：有默认授权时平日约 8 项/天，收尾日约 40 项（可以批量答复）；豁免只许 owner 立时约 14–20 项/天，超过 ≤15 的目标。因此创世策略必须带默认授权。

## 6. 公理推不出的东西

1. **义务是否充分**（②）：只能做到"说了的都兑现，没说的都显示为没说"，靠逃逸台账转成新律来补。
2. **律是否正确**：由人负责。系统提供的是：律带前提、撤销带影响范围、可执行反例能把问题退回立律者。
3. **信任根**：`L[0]` 由谁签、观察者怎样认证。在同一 OS 用户下只能防失误和偷懒；有人绕过 pi-dag 直接写，只能事后以漂移的形式记录。
4. **调度、模型和进程恢复**：归 dsa。
5. **给 owner 的解释、比较和建议**：属于呈现层，a2 只保证底层数据完整（每项欠都有主语、兑现者和前提）。

## 7. 待审问题

- **形式化验证**：三个 TLC 模型的结果见 `formal/README.md`。合入与判定、强度与避、权的委托与撤销三部分，在有限规模内都已检查。a2 → a2.2 的四处修补都来自模型给出的反例。还没检查：活性（每项欠最终都会被它的兑现者处理）、不增欠的细粒度、读取集追踪和缓存复用。
- **交叉豁免**：避只禁止自己豁免自己。如果写者 w1 获得了豁免权，它就能豁免兄弟节点 n2，同一计划里的写者可以互相放行。这是要写进默认授权表（只授权父级和 owner），还是把避扩大到"同一计划的写者"？
- **不增欠的粒度**：要求义务细到单个用例或单条违例，否则旧欠和新欠会混在一起，分不出新增了什么。
- **读取集追踪的成本和覆盖**：用 strace、fanotify 还是语言层 hook？目录枚举怎么计入？J1 的 nodes.json 能否按 JSON 路径细分？
- **避里"作者"的边界**：父级拼出的候选、由模板生成的测试，算不算作者？
- **默认授权表的具体内容**：直接决定 owner 的待决量。
- **自评 ✔5 / ◐5 / ✘4 需要复审**；是否再做一轮对抗审查，由 owner 决定。
